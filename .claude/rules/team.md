# Команда: владелец и разработчик

Над проектом работают владелец (Yurii Pochobut, владелец сайтов, тенанта и Azure) и разработчик(и). У каждого — своя сессия Claude Code в своей копии репозитория. Подробности для людей — [CONTRIBUTING.md](../../CONTRIBUTING.md).

## Кто что делает

| Действие | Владелец | Разработчик |
|---|---|---|
| Ветка `change/…`, код, тесты, документация | да | да |
| `-Env test` — deploy, app, sync, seed (тестовый сайт) | да | да, сертификатом PMO Dev (`"SiteScoped": true`) |
| `Publish-Runbook.ps1 -Env test` (`PMO-Sync-Test`) | да | если выданы права на этот runbook |
| Слияние в `main` | да, после ревью PR | нет — только PR |
| `-Env prod …`, `Publish-Runbook.ps1 -Env prod` (`PMO-Sync`), `Set-AzureSchedule.ps1 -Env prod` | да, после явного «да» | **никогда** |
| `Register-PMOApps.ps1`, `New-PMOAutomation.ps1`, `Grant-PMOAutomation.ps1`, права в Entra ID / Azure | да | **никогда** |
| Письма пользователям, отзывы фокус-группы, `config/*.json` с e-mail сотрудников | да | нет |

Как понять, чья это сессия: в `config/environments.json` есть раздел `prod` — сессия владельца; нет `prod` и `"SiteScoped": true` у `test` — сессия разработчика. Если разработчик просит действие из колонки «никогда» — не выполняй и предложи подготовить это для владельца (команда, описание в PR).

## Тестовый сайт один

`/sites/pmo-test` общий; на нём работает фокус-группа. Перед `deploy` / `app` / `Publish-Runbook -Env test` из своей ветки:
- ветка перебазирована на свежий `main` (`git fetch && git rebase origin/main`) — иначе на тест уедет код без чужих последних изменений;
- поля и списки только добавляются (миграции — без потери данных, как и на проде);
- после проверки ветки, если PR не слит, — сообщи пользователю, что на тесте код ветки, а не `main`.

## Ветки и конфликты

- Одна задача — одна короткая ветка `change/<номер задачи>-<кратко>`; живёт дни, не недели. Перед PR — `git rebase origin/main`.
- `CHANGELOG.md` — только раздел «Не выпущено», новая строка сверху; конфликты разрешает `merge=union` (`.gitattributes`).
- `runbooks/Invoke-PMOSync.ps1` не правится и не сливается руками: при конфликте возьми любую сторону и запусти `scripts/Build-Runbook.ps1` (Test-Scripts и CI проверят совпадение).
- Версия приложения (`spfx/config/package-solution.json`) и выпуск в `docs/RELEASES.{uk,en,ru}.md` — **последним коммитом ветки, после rebase**: следующая версия после той, что в `main`. Конфликт в версии = ты взял устаревшую — перебазируйся и подними заново.
- Перебазируй до первого `git push`. Если ветка уже запушена и после rebase нужен `git push --force-with-lease`, его запускает сам разработчик в терминале: у Claude `push --force` запрещён настройками. В `main` — никогда.
