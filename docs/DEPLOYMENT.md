# Портфель проєктів — развёртывание в SharePoint Online

## Состав пакета

| Файл | Назначение |
|---|---|
| `Register-PMOApps.ps1` | Регистрирует в Entra ID два приложения: PMO Deploy (вход администратора) и PMO Sync (app-only по сертификату) |
| `Deploy-PMO.ps1` | Создаёт и обновляет сайт, списки, поля, формы, права списков, форматирование, представления, дашборд, переводы |
| `gallery-view.json` | Оформление плиток; должен лежать рядом с `Deploy-PMO.ps1` |
| `Invoke-PMOSync.ps1` | Логика портала по расписанию: отчёт → карточка, журнал, архив, последний комментарий, права по иерархии, напоминания |
| `pmo-prototype.html` | Интерактивный прототип интерфейса — эталон дизайна для будущего приложения SPFx |

Все скрипты идемпотентны: повторный запуск ничего не дублирует. Потоки Power Automate больше не нужны — их работу выполняет `Invoke-PMOSync.ps1`.

## Что создаётся

**Сайт** — сайт-коммуникация `/sites/pmo`. Язык по умолчанию — украинский, дополнительные — английский и русский. Создаётся группа `PMO-адміністратори` с полным доступом.

**Списки:**

| Список | Назначение и ключевые поля |
|---|---|
| Проєкти | название, код, ссылка на Loop, тип (Стратегічний / Звичайний), PM, Власник, Стейкхолдери (несколько пользователей), напрям, статус, пріоритет, загальний стан, % виконання, даты старта, запуска, завершения (план), прогноз, дата архивации, бюджет и факт, освоение, последний статус-отчёт, последний апдейт, последний комментарий, описание |
| Статус-звіти | проект, дата, период, три оценки (терміни, бюджет, ресурси), **вычисляемое** общее состояние, новые значения ключевых показателей (статус, тип, %, даты, затраты), причина их изменения, сделано / план / проблемы, требуется ли решение руководства |
| Ризики та проблеми | проект, тип, вероятность, влияние, оценка (вычисляемая), владелец, статус, срок, меры |
| Зміни показників | журнал: проект, дата, кто изменил, тип изменения, поле, было, стало, причина. Для пользователей — только чтение |
| Коментарі | проект, текст; автор и дата — стандартные поля |

Все дочерние списки связаны с проектом подстановкой с запретом удаления. Служебные поля (`pmoAcl`, `srApplied`) скрыты.

**Формы.** Ключевые показатели проекта нельзя изменить в форме редактирования карточки — только через статус-отчёт. К ним относятся статус, состояние, тип, % выполнения, все даты и затраты. При создании проекта статус, тип и даты задаются.

**Форматирование:**
- светофоры состояния без текста;
- иконки приоритета (⏫ ＝ ⏬);
- щит с мечом у стратегических проектов;
- полоса прогресса;
- светофор свежести отчёта;
- красная просроченная дата.

**Порядок колонок** во всех списках: первая — стратегический проект (щит с мечом), вторая — приоритет, третья — название проекта, дальше остальные. В приложении SPFx заголовки первых двух колонок — иконки компаса и флажка. В стандартных списках SharePoint заголовок колонки может быть только текстом, поэтому там они называются «Стратегічний» и «Пріоритет».

«Последний апдейт» и «Последний комментарий» показываются в широкой колонке, до трёх строк; полный текст виден во всплывающей подсказке.

**Представления** (без группировок):
- Проєкти: «Усі елементи» (без архива), «Стратегічні», «Проблемні», «Мої проєкти», «Немає свіжого звіту», «Архів», «Плитки»;
- Статус-звіти: «Потребують рішення»;
- Ризики та проблеми: «Відкриті».

**Дашборд** (главная страница):
- сверху две диаграммы Quick chart: «Портфель за станом» (круговая: активные проекты по общему состоянию) и «Проєкти за статусом» (столбцы) — числа в них записывает синхронизация;
- ниже во всю ширину «Проблемні проєкти», «Немає свіжого статус-звіту», «Потребують рішення керівництва», «Відкриті ризики»;
- копии страницы на английском и русском.

## Установка

Нужны PowerShell 7.2+, модуль PnP.PowerShell и права глобального администратора или администратора SharePoint.

```powershell
Install-Module PnP.PowerShell -Scope CurrentUser
```

1. **Приложение для развёртывания:**
   ```powershell
   ./Register-PMOApps.ps1 -Stage Deploy -Tenant contoso.onmicrosoft.com
   ```
   Скрипт выведет ClientId приложения PMO Deploy.

2. **Развёртывание:**
   ```powershell
   ./Deploy-PMO.ps1 -TenantName contoso -ClientId <PMO Deploy> -Owner yurii@contoso.com
   ```

3. **Приложение синхронизации** (по умолчанию доступ только к сайту портала — Sites.Selected):
   ```powershell
   ./Register-PMOApps.ps1 -Stage Sync -Tenant contoso.onmicrosoft.com -SiteUrl https://contoso.sharepoint.com/sites/pmo -DeployClientId <PMO Deploy>
   ```
   Скрипт выведет ClientId приложения PMO Sync, отпечаток сертификата и путь к файлам `.pfx` / `.cer`. Если напоминания по почте не нужны, добавьте `-NoMail`.

4. **Люди:**
   - сотрудников, которые будут работать с порталом, добавьте в «Участники сайта» — можно группу «Все, кроме внешних пользователей»;
   - руководителей PMO — в `PMO-адміністратори`.

   Участие в сайте даёт право создавать записи. Видеть проект будут только те, кому его откроет синхронизация.

5. **Руководители в Entra ID.** У сотрудников должно быть заполнено поле «Руководитель» (Manager): по нему строятся права по иерархии.

6. **Первый запуск синхронизации — пробный:**
   ```powershell
   $pw = Read-Host -AsSecureString
   ./Invoke-PMOSync.ps1 -SiteUrl https://contoso.sharepoint.com/sites/pmo -ClientId <PMO Sync> -Tenant contoso.onmicrosoft.com `
       -CertificatePath "./certs/PMO Sync.pfx" -CertificatePassword $pw -DryRun
   ```
   Затем тот же запуск без `-DryRun`.

7. **Расписание** — см. следующий раздел.

8. **Дашборд.** Диаграммы на главной настраивать не нужно: их заполняет синхронизация (пункт 8 в следующем разделе). До регистрации приложения синхронизации их можно заполнить приложением развёртывания: `Invoke-Env.ps1 -Action charts`.

## Синхронизация (Invoke-PMOSync.ps1)

Что делает каждый запуск:

1. **Отчёт → карточка.** Каждый ещё не применённый статус-отчёт переносит в проект статус, тип, % выполнения, даты и затраты. Если отчёт самый свежий по дате, переносятся ещё общее состояние, дата отчёта и «Останній апдейт». Отчёт отмечается как применённый.
2. **Архив.** Если в отчёте статус «Завершено», проект получает статус «Архівний» и дату архивации. Он пропадает из рабочих представлений и дашборда и остаётся в представлении «Архів».
3. **Журнал.** По каждому изменённому показателю — строка в «Зміни показників»: было, стало, автор отчёта, причина. Для нового проекта — строка «Створення».
4. **Комментарии.** «Останній коментар» в карточке — последний комментарий из списка «Коментарі» с автором и датой.
5. **Тип проекта** копируется в колонку «Стратегічний» отчётов и рисков.
6. **Права** на проект и все его записи — по таблице в разделе «Доступ». Пересчитываются только там, где изменился круг участников. Уже выданные права сравниваются по хэшу в поле `pmoAcl`.
7. **Напоминания** (с ключом `-SendReminders`). Каждому PM уходит одно письмо со списком его активных проектов без отчёта дольше `-ReminderDays` дней (по умолчанию 7).
8. **Диаграммы на главной** и её копиях EN / RU. Quick chart, подключённый к списку, строит точку на каждый элемент и не умеет считать элементы по группам, поэтому числа считает синхронизация и записывает в диаграммы как введённые вручную. Страница публикуется, только если числа изменились. Активные проекты — все, кроме «Скасовано», «Архівний», «Завершено». Цвета секторов Quick chart не настраиваются: порядок секторов подобран под его палитру (зелёный показывается синим). Только диаграммы: ключ `-ChartsOnly`.

**Расписание:**
- синхронизация — каждые 10–15 минут;
- `-SendReminders -ReminderFrom pmo@contoso.com` — раз в неделю, например в понедельник утром;
- `-RebuildPermissions` — раз в неделю ночью, чтобы учесть смену руководителей в Entra ID.

Где запускать:
- **Azure Automation:** runbook PowerShell 7.4; импортируйте модуль PnP.PowerShell; загрузите сертификат `.pfx` в «Сертификаты» учётной записи; в runbook передавайте `-Thumbprint`. Можно также подключаться через управляемое удостоверение (`-ManagedIdentity`) — тогда права Sites.Selected, User.Read.All и Mail.Send выдаются удостоверению.
- **Сервер Windows:** «Планировщик заданий», `pwsh.exe -File Invoke-PMOSync.ps1 …`; сертификат — в хранилище компьютера, в скрипт передаётся `-Thumbprint`.

Изменения из статус-отчёта попадают в карточку с задержкой до одного интервала расписания. Приложение SPFx (см. ниже) сможет сохранять карточку сразу, а синхронизация останется страховкой.

**Mail.Send.** По умолчанию это разрешение позволяет приложению отправлять письма от любого ящика. Ограничьте его одним ящиком PMO политикой Exchange Online:
```powershell
New-DistributionGroup -Name "PMO Sync senders" -Type Security -Members pmo@contoso.com
New-ApplicationAccessPolicy -AppId <PMO Sync> -PolicyScopeGroupId "PMO Sync senders" -AccessRight RestrictAccess -Description "PMO reminders only"
```

## Доступ

| Кто | Права на проект, его отчёты и риски | Комментарии и журнал |
|---|---|---|
| PM | редактирование | чтение, добавление комментариев |
| Руководители PM по цепочке Entra ID | редактирование | то же |
| Собственник | редактирование | то же |
| Каждый стейкхолдер | просмотр | то же |
| Руководители Собственника и стейкхолдеров | просмотр | то же |
| `PMO-адміністратори`, владельцы сайта | полный доступ | полный доступ |

Остальные пользователи проект не видят. Это касается списков, плиток, списков на дашборде и поиска. Исключение — диаграммы на главной: в них общее количество проектов по состоянию и статусу, без названий, одинаковое для всех.

**Power BI** читает данные от имени владельца набора данных и видит всё. Если отчёт будет открыт PM, настройте в нём RLS (ограничение строк) по e-mail участников — либо давайте доступ к отчёту только группе PMO.

## Ключевые показатели и общее состояние

Статус, общее состояние, тип, % выполнения и даты меняются только через статус-отчёт. Если в отчёте изменены статус, тип или даты, заполните «Причина зміни показників» — она попадёт в журнал. В приложении SPFx это поле будет обязательным.

Общее состояние отчёта — худшая из трёх оценок (терміни, бюджет, ресурси); вручную его не выбирают:

| Оценки | Общее состояние |
|---|---|
| хотя бы одна красная | червоний |
| хотя бы одна жёлтая, красных нет | жовтий |
| все зелёные | зелений |

Состояние проекта берётся из последнего статус-отчёта.

Та же формула — в вычисляемом столбце «Загальний стан» и в синхронизации.

## Оценка рисков

В форме риска заполняются два поля, оба по шкале от 1 до 5. Подсказки к шкалам видны в форме.

| Балл | Ймовірність | Вплив |
|---|---|---|
| 1 | рідко, до 10% | незначний: не влияет на сроки и бюджет |
| 2 | малоймовірно, 10–30% | помірний: отклонение в пределах резерва |
| 3 | можливо, 30–60% | суттєвий: сдвиг этапа или перерасход до 10% |
| 4 | ймовірно, 60–90% | значний: сдвиг запуска или перерасход более 10% |
| 5 | майже напевно, более 90% | критичний: срыв целей проекта |

**Оцінка** — вычисляемый столбец: вероятность × влияние, от 1 до 25.

| Оценка | Уровень |
|---|---|
| 15–25 | высокий (красный) |
| 8–14 | средний (жёлтый) |
| 1–7 | низкий (зелёный) |

Риски по умолчанию сортируются по оценке — самые опасные сверху.

## Три языка

Каждый видит сайт на языке своего профиля Microsoft 365.

Переводятся:
- интерфейс SharePoint;
- названия сайта, списков и столбцов;
- главная страница (отдельные копии EN и RU).

Остаются на украинском:
- значения выбора (статусы, состояния, типы);
- названия представлений;
- содержимое записей.

Язык сайта по умолчанию после создания изменить нельзя.

## Интерфейс

Стандартные списки и страницы SharePoint работают сразу после развёртывания. Дизайн из прототипа — «воздушный» интерфейс, светлая и тёмная темы, плитки, таблицы с выбором колонок, сортировкой и фильтрами, форма статус-отчёта с расчётом состояния — стандартными средствами SharePoint не повторить. Его реализует приложение SPFx (React) на странице сайта:
- данные оно берёт из тех же списков от имени пользователя, поэтому права работают автоматически;
- журнал и перенос показателей оно может выполнять сразу при сохранении.

Это отдельный следующий этап. Прототип `pmo-prototype.html` — его техническое задание.

## Обновление с предыдущей версии скрипта

`Deploy-PMO.ps1` сам выполняет миграцию:
- «Product» (один пользователь) переносится в «Стейкхолдери» и удаляется;
- «Загальний стан» в статус-отчётах пересоздаётся как вычисляемый по новой формуле (худшая из трёх оценок); поле «Обсяг та якість» удаляется;
- статус-отчёты, созданные до появления синхронизации, отмечаются применёнными, чтобы не задвоить журнал.

Если раньше вы настроили потоки Power Automate из прежней версии README, отключите их перед запуском синхронизации.
