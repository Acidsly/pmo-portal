# Портфель проєктів — развёртывание в SharePoint Online

## Состав

| Файл | Назначение |
|---|---|
| `scripts/Register-PMOApps.ps1` | Регистрирует в Entra ID приложения: PMO Deploy (вход администратора), PMO Automation (развёртывание по сертификату), PMO Sync (синхронизация, app-only по сертификату) |
| `scripts/Deploy-PMO.ps1` | Создаёт и обновляет сайт, списки, поля, связи, переводы, видимость полей в стандартных формах, права списков, представления, меню |
| `scripts/Deploy-App.ps1` | Собирает приложение SPFx и устанавливает его на сайт; страница `Portal` на весь экран — главная |
| `scripts/Invoke-PMOSync.ps1` | Логика по расписанию: отчёт → карточка, журнал, архив, последний комментарий, права по иерархии, напоминания |
| `scripts/Invoke-Env.ps1` | Запуск всего перечисленного с параметрами окружения из `config/environments.json` |
| `scripts/Seed-TestData.ps1` | Демонстрационные данные для тестового сайта |
| `spfx/` | Приложение SPFx — интерфейс портала по прототипу |
| `prototype/pmo-prototype.html` | Прототип интерфейса — эталон ([PROTOTYPE.md](PROTOTYPE.md)) |

Все скрипты идемпотентны: повторный запуск ничего не дублирует. Power Automate и Power Apps не используются.

## Что создаётся

**Сайт** — сайт-коммуникация `/sites/pmo`. Язык по умолчанию — украинский, дополнительные — английский и русский. Создаётся группа `PMO-адміністратори`: просмотр всех проектов и создание новых (у ранее развёрнутых сайтов полный доступ группы снимается).

**Списки:**

| Список | Назначение и ключевые поля |
|---|---|
| Проєкти | название, код, ссылка на Loop, тип (Стратегічний / Звичайний), PM, Власник, Стейкхолдери (несколько пользователей), напрям, статус, пріоритет, загальний стан, % виконання, даты старта, запуска, завершения (план), прогноз, дата архивации, бюджет и факт, освоение, последний статус-отчёт, последний апдейт, последний комментарий, описание |
| Статус-звіти | проект, дата, период, три оценки (терміни, бюджет, ресурси), **вычисляемое** общее состояние, новые значения ключевых показателей (статус, тип, %, даты, затраты), причина их изменения, сделано / план / проблемы, требуется ли решение руководства |
| Ризики та проблеми | проект, тип, вероятность, влияние, оценка (вычисляемая), владелец, статус, срок, меры |
| Зміни показників | журнал: проект, дата, кто изменил, тип изменения, поле, было, стало, причина. Для пользователей — только чтение |
| Коментарі | проект, текст; автор и дата — стандартные поля |

Все дочерние списки связаны с проектом подстановкой с запретом удаления. Служебные поля (`pmoAcl`, `srApplied`) скрыты.

**Формы.** Ключевые показатели проекта нельзя изменить в форме редактирования карточки — только через статус-отчёт. К ним относятся статус, состояние, тип, % выполнения, все даты и затраты. При создании проекта статус, тип и даты задаются.

Стандартные формы списков остаются для администраторов; пользователи работают в формах приложения.

Встроенные комментарии SharePoint в списках выключены: комментарии к проекту — список «Коментарі».

**Представления** стандартных списков — простые таблицы без оформления (для администраторов, выгрузок в Excel и Power BI), без группировок:
- Проєкти: «Усі проєкти» (по умолчанию, без архива), «Стратегічні», «Проблемні», «Мої проєкти», «Немає свіжого звіту», «Архів»;
- Статус-звіти: «Усі звіти», «Потребують рішення»;
- Ризики та проблеми: «Відкриті» (по умолчанию), «Усі ризики».

**Меню сайта:** Головна, Проєкти, Статус-звіти, Ризики та проблеми, Архів. Журнал и комментарии проекта — в его карточке в приложении, «Вміст сайту» — в меню «Параметры».

**Главная** — страница `SitePages/Portal.aspx` с приложением SPFx на весь экран (см. «Приложение SPFx»).

## Установка

Нужны PowerShell 7.2+, модуль PnP.PowerShell и права глобального администратора или администратора SharePoint.

```powershell
Install-Module PnP.PowerShell -Scope CurrentUser
```

1. **Приложение для развёртывания:**
   ```powershell
   ./Register-PMOApps.ps1 -Stage Deploy -Tenant contoso.onmicrosoft.com
   ```
   Скрипт выведет ClientId приложения PMO Deploy.

2. **Развёртывание:**
   ```powershell
   ./Deploy-PMO.ps1 -TenantName contoso -ClientId <PMO Deploy> -Owner yurii@contoso.com
   ```

3. **Приложение синхронизации** (по умолчанию доступ только к сайту портала — Sites.Selected):
   ```powershell
   ./Register-PMOApps.ps1 -Stage Sync -Tenant contoso.onmicrosoft.com -SiteUrl https://contoso.sharepoint.com/sites/pmo -DeployClientId <PMO Deploy>
   ```
   Скрипт выведет ClientId приложения PMO Sync, отпечаток сертификата и путь к файлам `.pfx` / `.cer`. Если напоминания по почте не нужны, добавьте `-NoMail`.

4. **Люди:**
   - сотрудников, которые будут работать с порталом, добавьте в «Участники сайта» — можно группу «Все, кроме внешних пользователей»;
   - руководителей PMO — в `PMO-адміністратори`.

   Участие в сайте даёт право добавлять отчёты, риски и комментарии; новые проекты заводит только PMO. Видеть проект будут только те, кому его откроет синхронизация; править — только его PM.

5. **Руководители в Entra ID.** У сотрудников должно быть заполнено поле «Руководитель» (Manager): по нему строятся права по иерархии.

6. **Первый запуск синхронизации — пробный:**
   ```powershell
   $pw = Read-Host -AsSecureString
   ./Invoke-PMOSync.ps1 -SiteUrl https://contoso.sharepoint.com/sites/pmo -ClientId <PMO Sync> -Tenant contoso.onmicrosoft.com `
       -CertificatePath "./certs/PMO Sync.pfx" -CertificatePassword $pw -DryRun
   ```
   Затем тот же запуск без `-DryRun`.

7. **Приложение SPFx** — `Invoke-Env.ps1 -Action app` (см. «Приложение SPFx»).

8. **Расписание** синхронизации — см. следующий раздел.

## Синхронизация (Invoke-PMOSync.ps1)

Что делает каждый запуск:

1. **Отчёт → карточка.** Каждый ещё не применённый статус-отчёт переносит в проект статус, тип, % выполнения, даты и затраты. Если отчёт самый свежий по дате, переносятся ещё общее состояние, дата отчёта и «Останній апдейт». Отчёт отмечается как применённый.
2. **Архив.** Если в отчёте статус «Завершено», проект получает статус «Архівний» и дату архивации. Он пропадает из рабочих представлений и главной и остаётся в представлении «Архів».
3. **Журнал.** По каждому изменённому показателю — строка в «Зміни показників»: было, стало, автор отчёта, причина. Для нового проекта — строка «Створення».
4. **Комментарии.** «Останній коментар» в карточке — последний комментарий из списка «Коментарі» с автором и датой.
5. **Тип проекта** копируется в колонку «Стратегічний» отчётов и рисков.
6. **Права** на проект и все его записи — по таблице в разделе «Доступ». Пересчитываются только там, где изменился круг участников. Уже выданные права сравниваются по хэшу в поле `pmoAcl`.
7. **Напоминания** (с ключом `-SendReminders`). Каждому PM уходит одно письмо со списком его активных проектов без отчёта дольше `-ReminderDays` дней (по умолчанию 7).
8. **Правки карточки** из приложения (скрытое поле `pmEditLog`) переносятся в журнал видом «Редагування картки», поле очищается.

**Расписание:**
- синхронизация — каждые 10–15 минут;
- `-SendReminders -ReminderFrom pmo@contoso.com` — раз в неделю, например в понедельник утром;
- `-RebuildPermissions` — раз в неделю ночью, чтобы учесть смену руководителей в Entra ID.

Где запускать:
- **Azure Automation:** runbook PowerShell 7.4; импортируйте модуль PnP.PowerShell; загрузите сертификат `.pfx` в «Сертификаты» учётной записи; в runbook передавайте `-Thumbprint`. Можно также подключаться через управляемое удостоверение (`-ManagedIdentity`) — тогда права Sites.Selected, User.Read.All и Mail.Send выдаются удостоверению.
- **Сервер Windows:** «Планировщик заданий», `pwsh.exe -File Invoke-PMOSync.ps1 …`; сертификат — в хранилище компьютера, в скрипт передаётся `-Thumbprint`.

В стандартных списках изменения из статус-отчёта появляются с задержкой до одного интервала расписания; в приложении они видны сразу.

**Mail.Send.** По умолчанию это разрешение позволяет приложению отправлять письма от любого ящика. Ограничьте его одним ящиком PMO политикой Exchange Online:
```powershell
New-DistributionGroup -Name "PMO Sync senders" -Type Security -Members pmo@contoso.com
New-ApplicationAccessPolicy -AppId <PMO Sync> -PolicyScopeGroupId "PMO Sync senders" -AccessRight RestrictAccess -Description "PMO reminders only"
```

## Доступ

| Кто | Видит | Проект, отчёты, риски | Комментарии и журнал |
|---|---|---|---|
| PM | свой проект | редактирование | чтение, добавление комментариев |
| Руководители PM по цепочке Entra ID | проекты подчинённых | просмотр | то же |
| Собственник, стейкхолдеры | проект | просмотр | то же |
| Руководители собственника и стейкхолдеров | проекты, где роль у подчинённых | просмотр | то же |
| `PMO-адміністратори` | все проекты | просмотр; создание новых проектов | то же |
| Владельцы сайта | всё | полный доступ | полный доступ |

Проект в архиве — только просмотр для всех, включая PM; полный доступ — только у владельцев сайта. Статус-отчёт не от PM синхронизация не применяет.

Остальные пользователи проект не видят — ни в приложении, ни в списках, ни в поиске. Главная приложения считает сводку только по видимым пользователю проектам.

**Power BI** читает данные от имени владельца набора данных и видит всё. Если отчёт будет открыт PM, настройте в нём RLS (ограничение строк) по e-mail участников — либо давайте доступ к отчёту только группе PMO.

## Ключевые показатели и общее состояние

Статус, общее состояние, тип, % выполнения и даты меняются только через статус-отчёт. Если в отчёте изменены статус, тип или даты, заполните «Причина зміни показників» — она попадёт в журнал. В приложении это поле обязательно.

Общее состояние отчёта — худшая из трёх оценок (терміни, бюджет, ресурси); вручную его не выбирают:

| Оценки | Общее состояние |
|---|---|
| хотя бы одна красная | червоний |
| хотя бы одна жёлтая, красных нет | жовтий |
| все зелёные | зелений |

Состояние проекта берётся из последнего статус-отчёта.

Та же формула — в вычисляемом столбце «Загальний стан», в синхронизации и в приложении (общие тест-векторы `tests/cases/rag.json`).

## Оценка рисков

В форме риска заполняются два поля, оба по шкале от 1 до 5. Подсказки к шкалам видны в форме.

| Балл | Ймовірність | Вплив |
|---|---|---|
| 1 | рідко, до 10% | незначний: не влияет на сроки и бюджет |
| 2 | малоймовірно, 10–30% | помірний: отклонение в пределах резерва |
| 3 | можливо, 30–60% | суттєвий: сдвиг этапа или перерасход до 10% |
| 4 | ймовірно, 60–90% | значний: сдвиг запуска или перерасход более 10% |
| 5 | майже напевно, более 90% | критичний: срыв целей проекта |

**Оцінка** — вычисляемый столбец: вероятность × влияние, от 1 до 25.

| Оценка | Уровень |
|---|---|
| 15–25 | высокий (красный) |
| 8–14 | средний (жёлтый) |
| 1–7 | низкий (зелёный) |

В приложении новые риски сверху; по оценке сортирует щелчок по заголовку колонки.

## Три языка

Каждый видит сайт на языке своего профиля Microsoft 365.

Переводятся:
- интерфейс SharePoint;
- названия сайта, списков и столбцов;
- приложение: переключатель UA / EN / RU, по умолчанию — язык профиля.

Остаются на украинском:
- значения выбора (статусы, состояния, типы);
- названия представлений;
- содержимое записей.

Язык сайта по умолчанию после создания изменить нельзя.

## Приложение SPFx

Интерфейс из прототипа реализует приложение SPFx в папке `spfx/` (SPFx 1.23.2, React 17): главная, «Проєкти» (плитки и таблица с сортировкой, фильтрами и выбором колонок), «Статус-звіти», «Ризики та проблеми», «Архів» и карточка проекта в выдвижной панели (история изменений, комментарии, матрица состояний, отчёты, риски). Адрес `#вкладка/представление/id/форма` открывает нужную вкладку, карточку или форму.

Формы приложения — как в прототипе: новый проект и правка карточки, статус-отчёт (подстановка текущих показателей, живой расчёт стану, причина обязательна при смене статуса, типа или дат), риск (создание, правка, просмотр без прав) и комментарий. Приложение записывает от имени пользователя отчёты, риски, комментарии, новые проекты и правку карточки без ключевых показателей; ключевые показатели, журнал и права — синхронизация. Правка карточки кладёт «было / стало» в скрытое поле `pmEditLog`; синхронизация переносит его в журнал «Зміни показників» (вид «Редагування картки») и очищает. Сохранённое сразу видно в приложении, в стандартных списках — после ближайшей синхронизации. Оно работает с теми же списками от имени пользователя, поэтому каждый видит только свои проекты. Новые статус-отчёты сразу видны в карточке: приложение накладывает их по тем же правилам, что синхронизация, а в списки их переносит синхронизация.

Сборка и установка:
```bash
brew install node@22                                     # один раз; системный Node не меняется
scripts/spfx.sh npm ci                                   # зависимости
scripts/spfx.sh npm run test:unit                        # модульные тесты логики
pwsh -NoLogo -File scripts/Invoke-Env.ps1 -Env test -Action app   # сборка и установка на тестовый сайт
```
`Deploy-App.ps1` один раз создаёт каталог приложений сайта (нужны права администратора SharePoint), загружает и обновляет пакет и делает страницу `SitePages/Portal.aspx` (приложение на весь экран) главной.

Ограничения: над приложением остаётся полоса Microsoft 365 (в Teams её нет); размещённый workbench SharePoint снимается 2026-12-01 — отладка на странице тестового сайта с `?debug=true&noredir=true&debugManifestsFile=https://localhost:4321/temp/build/manifests.js` при запущенном `scripts/spfx.sh npm run start`.

## Обновление с предыдущей версии скрипта

`Deploy-PMO.ps1` сам выполняет миграцию:
- «Product» (один пользователь) переносится в «Стейкхолдери» и удаляется;
- «Загальний стан» в статус-отчётах пересоздаётся как вычисляемый по новой формуле (худшая из трёх оценок); поле «Обсяг та якість» удаляется;
- статус-отчёты, созданные до появления синхронизации, отмечаются применёнными, чтобы не задвоить журнал.

Если раньше вы настроили потоки Power Automate из прежней версии README, отключите их перед запуском синхронизации.

## Уборка прежней версии

До перехода на приложение SPFx интерфейс собирался стандартными средствами SharePoint. Этот код удалён, а на сайтах, развёрнутых раньше, остатки убирает раздел 9 `Deploy-PMO.ps1` (при каждом развёртывании, повторно ничего не делает):
- страница `SitePages/Dashboard.aspx` и её копии `en/`, `ru/` — в корзину сайта, только если главной уже стало приложение;
- служебный список «Показники портфеля» (`Lists/PortfolioStats`) — в корзину сайта;
- поля карточки `pmKState`, `pmKDates`, `pmKMoney`, `pmCardInfo` — удаляются (вычисляемые и служебные, пользовательских данных нет);
- представление «Плитки», JSON-форматирование столбцов и представлений, разделы стандартных форм — снимаются.

Из корзины сайта список и страницы можно восстановить в течение 93 дней. На `pmo-test` уборка выполнена 2026-09-25; на проде она пройдёт при первом развёртывании после подтверждения.
