## Что есть сейчас (исследование кода)

- **Дата отчёта** `srDate` — поле формы, правится вручную (`ReportForm.tsx:82`, прототип `reportForm` ~2174), по умолчанию сегодня; guard — не раньше последнего погодженого (`guard.ts:42`, `gOldDate`).
- **Период** `srPeriod` — Choice «Тиждень / 2 тижні / Місяць / Квартал» (`Deploy-PMO.ps1:322`), выбор в форме; синхронизация его не читает; показывается в просмотре отчёта и необязательной колонке.
- **Факт завершения** (#54, `forms.ts:112-116`, векторы `report-form.json`): обязателен при «Завершено» / «Скасовано»; не раньше старта (`errBeforeStart`), не позже даты отчёта (`errAfterReport`); сообщения — без дат.
- **«Потрібне рішення»**: текст не обязателен нигде.
- **Ошибка #77 (корень):** приложение пишет `srStatus` (и `srType`, даты, затраты) **только если отличается от карточки** (`data/write.ts:16-23`). PM оставил статус прежним → поле пустое → колонка «—». Касается **любого** отчёта с неизменённым статусом, не только «на основі повернутого». Прототип пишет статус и тип всегда (расхождение с эталоном).
- **Переключатели** (`.seg`, `.ragpick .opts`, `.opts.scale`): выбранный — фон `--bg` на дорожке `--bg-alt`; в тёмной теме это `#1c1c1e` на `#2c2c2e` — почти не отличается; нет состояний `:hover` и `:disabled`.
- **«Мета та опис»** — `<p class="desc">` без ограничений, переносы строк схлопываются.
- **Фильтр колонки «Звіт»** — по свежести (`freshBucket`); погодження — только метка `RepMark` (`p.lastRep`).

## Риски

- Смена смысла `srDate` («дата отчёта» → «дата подання»): прежние отчёты остаются со своими датами; правило «новее последнего применённого» — по той же дате (подання), поведение не меняется.
- Запись `srStatus` всегда: синхронизация не должна писать журнал при равном статусе — вектор обязателен.
- Мобильный аудит — объём заранее неизвестен; итог — список правок с согласованием, если затрагивает больше вёрстки, чем выравнивание.
