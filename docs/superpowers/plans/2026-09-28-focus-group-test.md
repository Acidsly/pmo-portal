## Задачи

### Задача 1. Доступ в карточке

Задачи 1 и 2 этапа 4 без изменений: поле `pmAccess`, его заполнение синхронизацией в проходе прав, общие векторы `tests/cases/access.json`, раздел «Доступ до картки» в приложении.

### Задача 2. Телефон и планшет

**Файлы:** `theme/overrides.scss` (раздел `@media`), при необходимости `components/*` (атрибуты, классы), `pages/*`.

Ширины: телефон ≤ 600 px, планшет 600–1024 px, книжная и альбомная ориентация. Правила прототипа (`@media` 520 / 560 / 680 / 720 / 920 / 1100) переносятся полностью, дальше — дополнения:
- нигде нет горизонтальной прокрутки страницы; прокручивается только таблица внутри своей рамки, колонка названия закреплена слева;
- панель инструментов списков (Список / Плитки, представление, колонки) переносится по строкам, выбор представления — на всю ширину;
- на телефоне «Проєкти» по умолчанию открываются плитками, если пользователь не выбирал сам;
- карточка и формы — на весь экран, крестик и кнопки сохранения всегда видны, отступы под «чёлку» и полосу жестов (`env(safe-area-inset-*)`);
- формы в одну колонку; поля ввода не меньше 16 px (iOS не увеличивает страницу при вводе), кнопки и цели касания от 40 px;
- всплывающие фильтры и выбор колонок помещаются в экран (на телефоне — снизу на всю ширину);
- шапка: вкладки прокручиваются, язык и тема — компактно;
- главная: кольцо и динамика друг под другом, блоки-таблицы — прокрутка внутри.

**Проверка:** рамка — только быстрый поиск поломок вёрстки; приёмку даёт реальное устройство (зум полей, safe-area, клавиатура в рамке не воспроизводятся). В Chrome — приложение во вложенной рамке 360, 390, 768, 820, 1024 px (рамка того же сайта сохраняет вход), каждый экран, карточка и все формы; скрипт ищет элементы шире экрана — 0 найденных. На реальных устройствах — ты: iPhone (Safari и приложение SharePoint), Android (Chrome и приложение SharePoint), iPad. **Первым делом** — открыть `Portal.aspx` в приложении SharePoint на телефоне: страницы-приложения SPFx оно может показывать ограниченно; если не показывает — в инструкции «открывать в браузере», в приложении SharePoint — ссылка на браузер.

### Задача 3. Кнопка «Відгук» и список «Відгуки»

**Файлы:** `scripts/Deploy-PMO.ps1` (список `Lists/Feedback`: текст, экран (адрес `#…`), устройство (ширина экрана, браузер), статус разбора: Новий / Прийнято / Відхилено / Зроблено, ответ; автор и дата — стандартные; участники сайта могут добавлять; настройки списка `ReadSecurity = 2` и `WriteSecurity = 2` — каждый видит и правит только свои, PMO-адміністратори (полный доступ) — все), `data/SpRepo.ts`, `components/Header.tsx`, `panels/FeedbackForm.tsx` (новый), `i18n/strings.ts`.

- Кнопка в шапке, форма в панели: «Що не так або що покращити?», экран подставляется сам. После сохранения — уведомление.
- Показывается, только если на сайте есть список «Відгуки» (его создаёт `Deploy-PMO.ps1` с ключом `-Feedback`, `Invoke-Env` передаёт его только для `test`), — на проде кнопки нет, пока список не создан решением.
- Выгрузка для разбора — стандартное представление списка или `Export`.

**Приёмка:** отзыв с телефона и с компьютера попадает в список с экраном и устройством; другой участник чужих отзывов не видит.

### Задача 4. «Довідка» и инструкция

**Файлы:** `docs/USER-GUIDE.md` (новый, на украинском), `panels/Help.tsx` (новый), `components/Header.tsx`, страница для рассылки (артефакт claude.ai).

Содержание: что такое портал; как открыть (компьютер, телефон, приложение SharePoint, добавить на главный экран); роли и что видит каждый; главная; проекты (плитки, список, фильтры, колонки, представления); карточка; новый проект; статус-отчёт (оценки, общий стан, ключевые показатели и причина, «Завершено»); риск; комментарий; архив; язык и тема; как оставить отзыв; **сценарии для фокус-группы** — 8–10 заданий «сделайте и оцените» по ролям. Язык — украинский (как сайт); в приложении «Довідка» показывает тот же текст.

**Приёмка:** текст сверен с приложением по каждому экрану (сверка «пункт инструкции → экран»: 0 расхождений).

### Задача 6. Фокус-группа в демо-проектах

**Файлы:** `scripts/Seed-TestData.ps1` — новый ключ `-Roles config/focus-group.json` (не в git: e-mail → PM / власник / стейкхолдер по кодам `TEST-NN`). Обычный `seed` пропускает существующие проекты целиком, поэтому роли назначаются отдельным проходом: для каждого проекта из файла `pmManager` / `pmOwner` / `pmStakeholders` перезаписываются, если отличаются (повторный запуск ничего не меняет), проекты не пересоздаются. `.gitignore` — `config/focus-group.json`; после теста файл удаляется (в нём e-mail сотрудников).

- Участники — в «Учасники сайта»; каждому минимум одна роль PM, одна власника и одна стейкхолдера, чтобы увидеть разные права; один-два человека без ролей — проверить, что чужие проекты не видны.
- Руководители в Entra ID — как есть (права по иерархии проверятся сами).
- После — `sync`: права и «Доступ до картки».

**Приёмка:** под учётной записью участника (проверяет он сам) видны только его проекты, правка — где он PM / власник.
