## Постановка

1. Новое значение «Фаза проєкту» — **«Підтримка»**: для проектов, которые не завершены, но требуют постоянного надзора. Переход туда и обратно, из любой активной фазы, — статус-отчётом PM с причиной и погодженням PMO, как любая смена фазы.
2. Три вкладки проектов: **«Поточні проєкти»** (сейчас «Проєкти», без підтримки), **«Проєкти підтримки»** (новая), **«Архівні проєкти»** (сейчас «Архів»).
3. Главная с переключателем «Поточні / Підтримки»; режимы полностью раздельные, включая очередь погодження.
4. Свежесть отчёта — по дням подачи: поточні — понедельник и четверг, підтримка — четверг; только погоджений отчёт, по дате подання.
5. Не делаем: часы ресурсов, бюджет по часам, задачи хелпдеска (R8), перевод существующих проектов скриптом. Письма-напоминания (`Invoke-PMOSync.ps1` раздел 6, `-SendReminders`, `ReminderDays = 7`) и дайджест (`PMO.Digest.ps1:22,48,74,278`, «понад 14 дн.») сейчас выключены — оставляем их пороги как есть; расхождение с правилом портала — известный долг, записываем в SPEC и ROADMAP.

## Подход

Вариант A спецификации: новое значение существующего поля `pmStatus` / `srStatus`, новых полей и миграций данных нет. Всё правило категории — в двух функциях, `isSupport` (`logic/status.ts`) и `Test-SupportStatus` (`PMO.Common.ps1`), с общими векторами. Строка «Підтримка» вне этих функций и списков значений запрещена (проверка в Jest и `Test-Scripts.ps1`).

### Правило свежести (общие векторы `tests/cases/fresh.json`)

- `REPORT_DAYS = { project: [1, 4], support: [4] }` (день недели ISO: 1 — понедельник, 4 — четверг). День недели — из ISO-строки даты через `Date.parse(iso + 'T12:00:00Z')` и `getUTCDay()`, как `daysBetween` (`logic/dates.ts`), чтобы граница не сдвигалась от часового пояса браузера.
- `missed(last, today, kind)` — число дней подачи `S` с `last < S < today`. В сам день подачи он ещё не пропущен.
- `freshness(last, today, kind)`: нет отчёта — `na`; `missed = 0` — `g`; `1` — `y`; `≥ 2` — `r`.
- `last` — `pmLastUpdate`: дата подання последнего погодженого отчёта (как сейчас).
- Категория — по текущей фазе: `kind = isSupport(status) ? 'support' : 'project'`.
- Подсказка: «Пропущено звітів: N · останній погоджений — <дата>» и, если есть, «звіт від <дата> на погодженні» (`lastRep`).
- Обязательные случаи в векторах: понедельник / вторник / четверг / пятница, отчёт в день подачи и вне его, смена месяца и года, переход в підтримку, нет отчётов, отчёт «в будущем» (`missed = 0`).
- **«Звіт вчасно %»** на главной (`analytics.ts:16`, сейчас `g || y`): вчасно = `missed = 0` (только зелёный) — каждый пропуск при двух отчётах в неделю заметен; формула и векторы — в этапе 4, свои для каждой категории.

### Разрешённые места строки «Підтримка»

`logic/status.ts`, `i18n/values.ts`, `i18n/strings.ts`, списки фаз (`defs.tsx`, `ProjectForm.tsx`, `ReportForm.tsx`), `Bits.tsx` (`SC`), `scripts/PMO.Common.ps1`, `scripts/Deploy-PMO.ps1`, `Seed-TestData.ps1` / `Refresh-TestData.ps1`, прототип (`VAL`, `STATUSES`, `STC`, его `isSupport`), `tests/cases/*.json`, `spfx/test/**`, `ai/evalCases.json`, `help/guide.ts` (генерируется), документация. Везде остальное — только через `isSupport` / `Test-SupportStatus`; проверка в `Test-Scripts.ps1`.

### Где проекты підтримки показываются

| Место | Поточні | Підтримка |
|---|---|---|
| «Поточні проєкти», представления `PV` (`views.ts`), прототип `visP` / `VIEWS` | да | нет |
| «Проєкти підтримки» (новая, `SV`) | нет | да |
| Главная (все блоки, KPI, кольцо, «Динаміка», риски, решения, очередь погодження) | режим «Поточні» | режим «Підтримка» |
| «Статус-звіти», «Ризики та проблеми» | да, + представление «Підтримка» | да |
| Выбор проекта в формах отчёта и риска (`ReportForm.tsx:33`, `RiskForm.tsx:29`), «Додати» в «Статус-звіти» / «Ризики» (`Reports.tsx:18`, `Risks.tsx:17`) | да — без изменений | да — без изменений |
| Колокольчик, журнал, права, карточка | без изменений | без изменений |

«Динаміка» режима «Поточні» исключает проекты, которые **сейчас** на підтримці, из всех срезов (решение 09.11). В режиме «Підтримка» — те же срезы с шагом 7 дней по проектам підтримки.

## Риски

| Риск | Что делаем |
|---|---|
| Свежесть по пн / чт сразу покрасит многие проекты в жёлтый / красный | ожидаемо: правило отражает практику; в заметках о выпуске — объяснение; при приёмке посмотреть на тестовых данных |
