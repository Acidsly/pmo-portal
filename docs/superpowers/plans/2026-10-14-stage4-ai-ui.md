# Этап 4 — помощник ИИ в форме статус-отчёта

Основа — план [2026-10-12-copilot-report-assistant.md](2026-10-12-copilot-report-assistant.md) (разделы 2, 4.3, 4.4; итоги этапов 1 и 2). Агент, prompt и набор проверок готовы ([copilot/README.md](../../../copilot/README.md)); логика `aiContext` / `aiCheck` / `aiReply` / `aiEval` — с тестами; поля `srAiCheck`, `srAiCheckedAt`, `srAiFilled` — на тестовом сайте.

**Итог этапа:** у пилотной группы на тестовом сайте форма отчёта с «Заповнити з ШІ» и «Перевірити з ШІ»; поле «Суперечності (аналіз ШІ)» видят PM, PMO и все, кто видит отчёт; остальные пользователи — форма как сейчас. Прод не трогаем.

Исполнитель — Claude; вы — решения (раздел «Решения»), приёмка на тестовом сайте. Срок — 3–4 рабочих дня (после кросс-ревью плана: прототип, три языка, документы, скриншоты и ревью кода — заметная часть).

## Как работает (для PM)

1. Форма «Новий статус-звіт» у пилота: вверху — **«Заповнити з ШІ»** (`wand-sparkles`).
   - Нажал → «ШІ готує чернетку…» (кнопка заблокирована, «Скасувати» — отмена запроса).
   - Ответ: пустые поля «Зроблено», «План», «Проблеми та ризики», «Резюме» заполняются сразу; заполненные — по одному вопросу «Замінити текст у полі «…»?» (Так / Ні); у формы — «Скасувати вставку ШІ» (один шаг, возвращает тексты до вставки).
   - Над полями — панель помощника: **«Що не забути»** (пункты) и **«ШІ пропонує оцінки»** — у каждой оценки «Терміни / Бюджет / Ресурси» подсказка «ШІ: Жовтий» и причина; оценку PM ставит сам (кнопка «Прийняти» у подсказки — ставит предложенную, решение остаётся за PM).
2. Внизу вместо «Зберегти» — **«Перевірити з ШІ»** (`scan-search`):
   - сначала обычные проверки формы (`reportErrors`) — ошибки у полей, ИИ не вызывается;
   - «ШІ аналізує…» → поле **«Суперечності (аналіз ШІ)»** (`sparkles`, свой цвет, только чтение) и сообщение «ШІ знайшов N суперечностей — виправте або збережіть як є» / «Суперечностей не знайдено»;
   - появляется **«Зберегти»**; изменил отчёт — снова «Перевірити з ШІ» (отпечаток `reportPrint`); ответ, пришедший после изменения формы, отбрасывается (`acceptReply`).
3. ИИ недоступен (ошибка, нет ответа 60 с, нет доступа, отказ фильтра) — текст причины и **«Зберегти без перевірки»**: в поле — «Перевірку ШІ не виконано: …» (`unavailableNote`), PMO это видит. Сдача отчёта не зависит от ИИ.
4. Первый вызов у человека — карточка согласия Copilot Studio. В форме: «Помічнику ШІ потрібен ваш дозвіл обробляти дані звіту (один раз)» — **«Дозволити»** / «Скасувати». «Скасувати» = ИИ недоступен (п. 3).
5. Просмотр отчёта и погодження PMO: поле «Суперечності (аналіз ШІ)» и «Перевірено ШІ: дд.мм.рррр гг:хв» или «Збережено без перевірки ШІ». Отчёт «на основі повернутого»: поле ИИ и дата не копируются.

## Задачи

### 1. Логика сценария формы (`logic/aiFlow.ts`, векторы `tests/cases/ai-flow.json`)
Чистые функции, без React (состояние формы — здесь, компонент только вызывает):
- `aiAction(s)` — что делает нажатие: порядок **ошибки формы (`reportErrors`) → «звіт уже на погодженні» (`pendingDate`) → ИИ**. Ошибки формы — показать у полей, ИИ не вызывать; на погодженні — обе кнопки ИИ и сохранение недоступны (как сейчас); «Зберегти без перевірки» тоже проходит `reportErrors` и блок «на погодженні».
- Кнопка внизу — `aiButton` + сброс недоступности: любое изменение отпечатка после ошибки ИИ снова даёт «Перевірити з ШІ» (PM может повторить после таймаута); во время запроса «Зберегти» недоступна.
- Согласие — автомат: запрос → карточка → «Дозволити» → ответ карточки → результат; повторная карточка или «Скасувати» → недоступно (`unavailableNote`).
- `prevCheck` — текст последней успешной проверки **в этой форме** (не `srAiCheck` старых отчётов): при открытии и «на основі повернутого» — пусто; «Перевірку ШІ не виконано» в `prevCheck` не попадает.
- Смена проекта в форме (`switchProject`) — сброс всего состояния ИИ: проверки, панели помощника, снимка вставки.
- «Скасувати вставку» доступна, только пока форма не менялась после вставки (отпечаток = отпечатку сразу после вставки) — правки PM не затираются.
- `aiView(aiCheck, aiCheckedAt)` для просмотра: дата есть — «Перевірено ШІ: …»; текст без даты — «Збережено без перевірки ШІ» (у пилота при недоступности всегда пишется `unavailableNote`); пусто — блока нет (старые отчёты и отчёты вне пилота).
- `checkText` — не длиннее 4000 знаков (вектор).
- `aiErrorKind(x)` — ответ / исключение агента → `'consent' | 'denied' | 'timeout' | 'credits' | 'error'`: `AccessToBotDenied` → denied; `AIModelActionBadRequest` (фильтр, пустой вход) → error; таймаут → timeout; код про ёмкость / кредиты (`*Capacity*`, `*Quota*`, `*RateLimit*`) → credits; карточка `aiPrompt/consentCard` → consent; остальное → error.
- `aiSaveFields(s)` → `{ srAiCheck, srAiCheckedAt, srAiFilled }` для записи: проверено — текст `checkText(items)` и время проверки; «без перевірки» — `unavailableNote`, время пусто; `srAiFilled` — была ли вставка из «Заповнити з ШІ».
- `draftInsert(form, draft)` — что вставить сразу, о каких полях спросить, снимок для «Скасувати вставку» (на основе `insertText`).
- Векторы: все коды ошибок; сохранение после проверки / без проверки / вне пилота (поля не пишутся); вставка в пустые и заполненные поля, отмена.

### 2. Вызов агента (`ai/aiAgent.ts`)
- **Новый разговор на каждый запрос** (агент историю не использует; никакой связи между проектами при смене проекта в форме): `ask(kind, contextJson)` → `{ ok, text } | { consent } | { error }`; таймаут 60 с через `AbortController`; повторный вызов во время запроса невозможен (кнопка заблокирована).
- Сообщение — `aiMessage(kind, json)`; ответ — последнее непустое сообщение; разбор — `parseDraft` / `parseCheck`; неразобранный ответ — один автоматический повтор, затем «ШІ повернув неочікувану відповідь — спробуйте ще раз» (= error).
- Токен — как в прототипе (`aiToken`: тихо, затем всплывающее окно) — **первым действием в обработчике нажатия**, до загрузки журнала и других `await` (иначе браузер блокирует окно входа); окно всё же заблокировано → «Дозвольте спливаючі вікна для сайту» (error).
- Модуль — отдельный файл, грузится только у пилота (`isAiPilot`). **Критерий:** основной файл сборки вырос не больше чем на 30 КБ; библиотеки агента и MSAL — только в подгружаемых файлах (размеры до / после — в отчёте сборки).

### 3. Данные (`data/map.ts`, `data/write.ts`)
- Чтение `srAiCheck`, `srAiCheckedAt` в `StatusReport` (`aiCheck`, `aiCheckedAt`); если полей на сайте нет — чтение без них (урок `fpDecidedAt`: страница не пустеет) **и в списке отчётов, и в `SpRepo.fresh`**, тест.
- Запись в `reportBody` — `aiSaveFields`; вне пилота — поля не передаются. Контекст для ИИ: журнал проекта — `repo.loadChanges(projectId)` при нажатии кнопки (один раз на форму); ошибка загрузки — контекст без журнала, ИИ всё равно вызывается.
- **Сохранение и свежие данные:** «Зберегти» по-прежнему берёт `repo.fresh` + `guard`; не прошло (отчёт погоджено / повернуто, PM сменился…) — как сейчас: сообщение и перезагрузка, **а проверка ИИ сбрасывается** (нужна новая). Срок жизни проверки — сессия формы; ИИ — подсказка, на погодження не влияет.
- Тесты: `formValues` / `write` — поля ИИ; чтение без полей.

### 4. Форма (`panels/ReportForm.tsx`) и компоненты
- Кнопки, панель помощника, поле ИИ, карточка согласия, состояния — по разделу «Как работает». Состояние формы — в `aiFlow` / `aiCheck`, в компоненте — только вызовы.
- Контекст — `buildReportContext` (проект формы, отчёты, риски, журнал, форма, прежняя проверка `prevCheck`); `tooLarge` → «Забагато даних для ШІ — збережіть без перевірки» (saveWithout).
- Язык ответа — язык интерфейса (`c.lang`).
- Телефон 375 px: кнопки друг под другом, без горизонтальной прокрутки.
- Тесты рендера (`spfx/test/components.test.tsx`, агент — заглушка): блок «на погодженні» — кнопки ИИ недоступны; ошибки формы — агент не вызван; «Зберегти» недоступна во время запроса; повтор после ошибки при изменении формы; смена проекта — сброс; оценки без «Прийняти» не меняются; кнопка по отпечатку; вставка и вопрос «Замінити текст?»; «Скасувати вставку»; опоздавший ответ отброшен; согласие; «Зберегти без перевірки» с причиной; поле ИИ только для чтения; вне пилота — форма как сейчас.

## Решения

**Приняты 13.10.2026 — по рекомендациям, план одобрен:** 1 — подсказка и «Прийняти»; 2 — список в коде; 3 — «Набір перевірок» для пилота по адресу; 4 — текст согласия ниже.


1. **Оценки ИИ:** подсказка у каждой оценки + кнопка «Прийняти» (рекомендую; оценку всё равно выбирает PM, без нажатия ничего не меняется — тест) — или только текст без кнопки.
2. **Список пилота:** в коде (`aiConfig.ts`, как сейчас; изменение — новой версией; рекомендую на время пилота) — или в настройках веб-части на странице (меняет владелец сайта без выпуска).
3. **Страница «Набір перевірок»** остаётся для пилота после этапа 4 — без пункта в меню, только по адресу (рекомендую: нужна при каждой правке prompt) — или убрать совсем.
4. **Текст согласия** (информированное согласие, раздел 9a): «Помічник ШІ надішле дані цього звіту й проєкту в Microsoft Copilot Studio (Європа; обробка моделлю може відбуватися за її межами). Дозволити? Запитуємо один раз.» — подходит?

## Риски

| Риск | Что делаем |
|---|---|
| Ответ ИИ 2–15 с, PM нажимает повторно или уходит | кнопка заблокирована, «Скасувати», опоздавший ответ отбрасывается |
| Карточка согласия или окно входа заблокированы | понятный текст и «Зберегти без перевірки» |
| Цена GPT-5 chat выше ожидаемой (PPAC 14.10) | модель меняется в prompt без выпуска портала; набор проверок — повторить |
| Поля ИИ не созданы на проде | `Deploy-PMO.ps1` до выкладки приложения; чтение без полей не ломает страницу |
| Известное ограничение c06 (третий пункт прошлого плана) | в «Довідці»: ИИ — подсказка, ответственность за отчёт — на PM |
