# Сповіщення, часть 1 — колокольчик в приложении

**Решение пользователя (08.10.2026):** блок сповіщень делим на две части. **Часть 1 (этот план)** — колокольчик в приложении и просмотр изменений: каждый в рамках своей роли видит, что есть новые события, и может пройти и посмотреть все изменения. **Часть 2 (позже)** — письма (раз в 15 минут и утренняя сводка) и лента активности Teams, по общему плану `2026-10-07-notifications.md`.

Ограничения из общих решений: руководители PM не участвуют; журнал остаётся только для чтения; «прочитано» — в новом скрытом списке «Прочитане» (строка на человека); профиль M365 не трогаем.

## Что увидит пользователь

- **Колокольчик в шапке** (рядом с «?») — красная точка, если есть новые для меня события. На сайте и во вкладке Teams (то же приложение).
- **Панель «Сповіщення»** (маршрут формы `notifications`): события за 14 дней, новые сверху и выделены, прочитанные ниже бледнее; по каждому — проект, вид («Подання звіту», «Погодження», «Ризик», «Коментар», …), что изменилось («було → стало»), кто, когда; нажатие открывает карточку, отчёт или риск. Фильтр «Лише нові».

## Кто что видит (`logic/notify.ts`, векторы `tests/cases/notify.json` — их же возьмёт синхронизация в части 2)

**Вид события** (`notifyKind`) из события истории (`toEvents`) и комментария: `created`, `assigned`, `submitted`, `decided` (Погоджено / Повернуто / авто-повернення), `applied` (отчёт применён, правка в обход откачена), `archived` (событие с «Статус → Архівний»), `risk`, `cardEdit`, `comment`.

**Получатель** (`notifyFor(me, событие, проект, контекст)`):

| Вид | PM | Власник | Команда | Власник ризику | PMO |
|---|---|---|---|---|---|
| created, assigned | ✓ | ✓ | ✓ | — | — |
| submitted | — | — | — | — | ✓ |
| decided, applied | ✓ | ✓ | ✓ | — | — |
| archived | ✓ | ✓ | ✓ | — | ✓ |
| risk | ✓ | оцінка ≥ 15 | оцінка ≥ 15 | ✓ | — |
| cardEdit | ✓ | ✓ | — | — | — |
| comment | ✓ | ✓ | ✓ | — | — |

- Роли — **сейчас** (PM, власник, команда из карточки; PMO — участник группы PMO или владелец сайта). PMO по чужим проектам — только `submitted` и `archived`.
- Своё событие — не показывается; пустой автор (действия синхронизации) — показывается всем по правилу.
- Архивный проект — только событие `archived`.
- Риск: оценка — текущая из записи риска (по `kcItem`); риска нет — из «Оцінка: було → стало» события; иначе — как < 15.
- Видимость данных — права SharePoint: приложение читает только журнал и комментарии проектов, к которым у человека есть доступ.

## Данные

- **Журнал:** при загрузке — строки за 14 дней (`kcDate ge …`, новый индекс `kcDate`) вместо нынешних «только переносы плановой даты» (те берутся из того же набора); комментарии уже загружаются полностью.
- **Новизна — по номеру записи** (`Id`): событие новое, если наибольший номер его строк > `nsReadId`; комментарий — если номер > `nsReadCmId`. Событие, которое синхронизация записала частями между двумя загрузками, после дописывания снова станет новым — целиком (номер события = наибольший номер строк), без дробления.
- **Список «Прочитане»** (`Lists/NotifyState`, скрытый): `Title` (e-mail, индекс), `nsUser`, `nsReadId`, `nsReadCmId` (числа). Поля писем (`nsMode`, `nsLang`, `nsMailed*`, `nsDigestAt`, `nsTeamsId`) — в части 2.
- **Права:** список — без доступа участникам; строку создаёт синхронизация и даёт права **только этому человеку** на новом уровне «Оновлення (портал)» (просмотр и правка элемента, без добавления и удаления). Лимиты: строк — по числу людей с доступом (десятки — сотни, порог 5 000 не грозит), уникальных прав — по одному на строку (предел 50 000, рекомендация до 5 000).
- **Запись приложением** — только свои `nsReadId` / `nsReadCmId`, со свежей версией (`If-Match`), метка только растёт (`max`). Исключение в CLAUDE.md из правила «приложение не пишет…».

## Синхронизация (новый раздел 7 «Сповіщення», после раздела 5 «Права»)

1. Люди — каждый из `pmAccess` любого проекта, участники группы PMO и владельцы сайта.
2. Нет строки — создать **одной записью сразу с метками** = текущий последний номер журнала и комментариев (первый запуск и новый человек не видят старое как новое), затем права на строку только этому человеку.
3. Метки в строках зажимаются в 0…последний номер (недоверие к записи пользователя); дубль строки или строка без человека — предупреждение.
4. Человек без доступа ко всем проектам — строка остаётся (не удаляем), прав на строку не меняем.
5. DryRun — только «создать строку: …», ничего не пишет.
6. Правило «кто что видит» синхронизации в части 1 не нужно.

## Этапы

1. **Правило** — `notifyKind`, `notifyFor`, `unreadEvents` (что новое, что прочитано, порядок) в `logic/notify.ts`; векторы `notify.json` по каждой строке матрицы и исключениям (своё событие, пустой автор, архив, риск ≥ 15 / < 15 / удалён, власник ризику, PMO по чужому проекту, частично записанное событие); мутационная проверка.
2. **Список и синхронизация** — Deploy: уровень «Оновлення (портал)», список «Прочитане», поля, индексы `Title` и `kcDate`, скрытие (раздел 8a), представление; синхронизация: раздел 7 (строки, метки, права, зажим), функция `Get-NotifyRowPlan` с векторами `notify-state.json` (новый человек, первый запуск, зажим, дубль); проверка на тесте: человек видит только свою строку и не может её удалить.
3. **Приложение** — загрузка журнала за 14 дней и своей строки, колокольчик с точкой, панель «Сповіщення», отметка прочитанного, подсказка «з'являться протягом 15 хвилин»; рендер в jsdom (точка есть / нет, открытие панели снимает точку и пишет метку, метка не уменьшается, нажатие открывает запись).
4. **Прототип** — колокольчик и панель в памяти страницы по тем же правилам; сценарии в jsdom (PM меняет риск — у PMO точки нет, у команды — только при оценке ≥ 15; комментарий — точка у PM и команды; открытие панели снимает точку).
5. **Документация и выкат** — SPEC, DATA-MODEL, ARCHITECTURE, DEPLOYMENT, CLAUDE.md, инструкции uk / en / ru + `npm run guide`, CHANGELOG, версия; тест-сайт: deploy → app → sync-dryrun → sync; проверка; runbook в Azure; кросс-ревью кода Sonnet; push — после «да».

## Риски

1. Журнал за 14 дней при каждой загрузке — больше данных, чем сейчас; фильтр по индексу `kcDate`, при росте — окно 7 дней.
2. «Прочитано до» — без отметки отдельных событий: открыл панель — прочитано всё показанное.
3. Демо-скрипты тестового сайта (Seed, Refresh) пишут в журнал — у всех появится точка; для части 1 допустимо (служебные записи — в части 2).
