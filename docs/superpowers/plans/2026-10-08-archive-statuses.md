# Архив по статусам «Завершено» / «Скасовано» (вместо «Архівний») — план

**Решение пользователя (08.10.2026):** в «Архіві» — проекты со статусом **Завершено** или **Скасовано**; статус **«Архівний» убираем**. Физически проекты, как и раньше, остаются в списке «Проєкти» — архив = отбор по статусу (права «только просмотр» — по статусу).

**Сложность:** средняя+ (≈ 40 файлов, правило есть и в синхронизации, и в приложении, и в прототипе; миграция данных на тесте; порядок выкладки важен — иначе синхронизация на время откроет архивные проекты на правку).

## Что сейчас

- Статусы проекта (`Deploy-PMO.ps1` `$status`): Ініціація, Планування, Реалізація, Призупинено, Скасовано, **Архівний**. Статусы отчёта (`$repStatus`): те же, но вместо «Архівний» — **Завершено**.
- Погоджений отчёт «Завершено» / «Скасовано» → синхронизация пишет проекту **«Архівний»** и `pmArchivedAt` (`Invoke-PMOSync.ps1` ~310; в приложении — наложение `logic/overlay.ts` ~27; прототип ~2222).
- «Архівний» как признак архива: синхронизация — права только чтение (`Get-Access … archived`), заморозка прав (`Test-ArchiveFrozen`), возврат отчётов на погодженні при архиве (`Get-PendingReturns`), решение PMO по архивному проекту не применяется (~842), показатели не применяются (`Get-ApplyAction`, ~918), комментарии запрещены (~1212); приложение — `isArch` (`logic/status.ts`: «Архівний» или «Завершено»), форма карточки закрыта (`ProjectForm`), колокольчик (`logic/notify.ts`: событие «→ Архівний» = archived; архивный проект — только это событие), отображение «Завершено → Архівний» в отчёте и колонке статуса отчёта (`ReportView`, `defs.tsx`).
- Тест-сайт: 5 архивных проектов, исход однозначно виден по последнему применённому отчёту: PRJ-008, PRJ-009, PRJ-015 — «Завершено»; PRJ-014, PRJ-016 — «Скасовано». Прод `/sites/ppm` ещё не создан — миграция нужна только тесту (и на всякий случай — идемпотентна).

## Как будет

- **Статусы проекта:** Ініціація, Планування, Реалізація, Призупинено, **Завершено**, **Скасовано**. «Архівний» исчезает из выбора после миграции.
- **Архив = статус Завершено или Скасовано.** Одна функция-признак: синхронизация — `Test-ArchivedStatus` (`PMO.Common.ps1`), приложение — `isArch` (`logic/status.ts`), прототип — `isArch`. Все проверки `-eq "Архівний"` / `=== 'Архівний'` заменяются вызовом признака.
- **Погоджений отчёт «Завершено» / «Скасовано»** → проект получает **этот же** статус (без подмены) и `pmArchivedAt` = дата отчёта.
- **Вкладка «Архів»:** колонка «Статус» — по умолчанию (Завершено / Скасовано, цветом), фильтр по ней; представление «Усі / Завершені / Скасовані» (вопрос 2). Карточка архивного проекта: «🔒 Проєкт завершено» / «Проєкт скасовано».
- **История:** старые записи журнала «→ Архівний» не переписываем (журнал — история); перевод значения «Архівний» в `values.ts` / `VAL` остаётся для их показа.

## Переходный период и порядок выкладки (важно, уточнён после кросс-ревью)

Синхронизация в Azure работает каждые 15 минут. Старая синхронизация не считает «Завершено» архивом и **выдала бы PM права на правку**; старое приложение не считает «Скасовано» архивом (проект попал бы в «Проєкти»); значение, которого нет в выборе `pmStatus`, записать нельзя; `F` не меняет выбор у существующего поля. Поэтому:

1. **Синхронизация первой** (runbook опубликован, `Build-Runbook.ps1` → `Publish-Runbook.ps1`): признак архива = Завершено / Скасовано / **Архівний** (переходное); при применении итогового отчёта пишет статус отчёта, **только если он уже есть в выборе `pmStatus`** (выбор читается один раз за запуск), иначе — по-старому «Архівний». `acl-export` до → `sync-dryrun` → `sync` → `acl-export` после: права не изменились.
2. **Приложение** (понимает оба варианта) — до миграции.
3. **Deploy:** (а) явный блок выбора `pmStatus` (`Set-PnPField … Choices`, как для `kcKind` / `fbStatus`): добавить «Завершено»; (б) **старый блок «Скасовано → Архівний» (`Deploy-PMO.ps1:478-509`) удалить** — иначе каждый deploy возвращал бы «Скасовано» в «Архівний»; (в) миграция `Архівний → Завершено / Скасовано`; (г) убрать «Архівний» из выбора — только при 0 проектов с ним и без предупреждений миграции; (д) представления.
4. Синхронизация `sync-dryrun` → `sync` и `acl-export`: 0 изменений прав (отметка `arch2:` зависит от признака архива, а не от названия статуса).
5. Позже, отдельным изменением — убрать «Архівний» из признака архива и проверку выбора в синхронизации.

Проекты со статусом «Скасовано», которые раньше не были архивом, получили бы `v2:` → `arch2:` и пересчёт прав на «только чтение»; на тесте таких нет (прежняя миграция перевела их в «Архівний»), прода ещё нет.

## Миграция `Архівний → Завершено / Скасовано` (Deploy, идемпотентна)

- Для каждого проекта с «Архівний» исход (по порядку): (1) статус отчёта из эталона `psLastApplied`, если он «Завершено» / «Скасовано»; (2) иначе — новейший применённый отчёт с итоговым статусом (по дате, затем номеру; `FileSystemObjectType -ne Folder`); (3) иначе запись журнала «Скасовано → Архівний» (прежняя миграция отменённых) → «Скасовано»; (4) иначе проект **остаётся «Архівний»** (не угадываем) с предупреждением на каждом deploy — тогда «Архівний» из выбора не убирается (после кросс-ревью кода).
- Обновить карточку (`pmStatus`, `SystemUpdate`, без смены прав) **и эталон** (`Sync-ProjectStateFromCard`) — иначе синхронизация откатит статус.
- Запись журнала — вопрос 1 (по умолчанию — **без записи**: это переименование значения, а не событие; запись дала бы всем участникам ложные сповіщення).
- Векторы `tests/cases/archive-migration.json` (последний отчёт «Завершено» / «Скасовано»; несколько итоговых отчётов — новейший; нет отчёта, есть строка журнала; нет ничего → «Завершено» + предупреждение; не «Архівний» — не трогаем) — общие для `Test-Scripts.ps1`.
