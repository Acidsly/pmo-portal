# Прототип ↔ тестовый портал: полная сверка и план выравнивания

Дата: 18.10.2026. Повод: «головні відрізняються, перевіряй все й досконало».

## Как сверяли

1. **Вид в браузере.** Портал (Chrome, ваша учётная запись, только просмотр — ничего не сохранялось) и прототип в одинаковом окне 1910×1267. Снимок вычисленных стилей каждого элемента (32 свойства, размеры), сравнение скриптом: «Головна», «Проєкти» (плитки и список), «Статус-звіти», «Ризики», «Архів», «Відгуки», карточка проекта, просмотр отчёта, формы отчёта и риска.
2. **Код, по реестру.** Четыре независимые сверки, каждая — полный список элементов и правил своей области, у каждого пункта: совпадает / отличается / только портал / только прототип.

| Область | Проверено пунктов | Расхождений |
|---|---|---|
| «Головна» и списки | 192 | 36 |
| Карточка проекта и боковые окна | 104 | 38 |
| Формы и просмотр отчёта | ≈185 | 47 |
| Шапка, тексты, стили (`overrides.scss`) | ≈690 | ≈60 |

Что **совпадает полностью**: словари текстов (T 432, FLD 63 ключа), переводы значений (60 ключей × 3 языка), сгенерированные стили, значки, порядок блоков «Головної», формулы показателей, представления всех списков, колонки по умолчанию.

Откуда расхождения: (а) стили, которые есть только в приложении (`overrides.scss`) — в прототипе их нет; (б) правила, которые приложение получило позже (#87, #95, …), а прототип нет; (в) мелочи приложения, сделанные «не как в прототипе» (кнопка ×, значки, размеры аватаров, тексты в EN/RU).

## A. Прототип догоняет портал — портал верен

**Головна и списки**
- A1. Строки «Проблемні проєкти» и других таблиц — в порядке «стратегічні → пріоритет → назва» (сейчас — порядок хранения).
- A2. Сдвиги сроков и запуски — те же правила при равенстве (дни → переносы → №; дата → №).
- A3. «Портфель за напрямами»: состояние не из трёх цветов — «не оцінено»; при равенстве — по переведённому названию (так же исправить и портал: сейчас по украинскому).
- A4. Тип риска, подсказки приоритета и состояния, подписи фильтров (тип, фаза, PM, стратегічний, пріоритет) — на языке интерфейса.
- A5. «Статус-звіти»: колонка «Потрібне рішення» (с текстом решения в подсказке), «%» без значения — «—», подсказки у «Зроблено / План / Проблеми», порядок по умолчанию — дата подання, затем создание.
- A6. «Ризики»: порядок по умолчанию — новые сверху (как решено раньше, SPEC 15).
- A7. Плитки: без PM — блок PM не выводится; режим «Список / Плитки» запоминается; «Архів» по умолчанию — список.

**Карточка и сповіщення**
- A8. Підрозділ и тип проекта в карточке — на языке интерфейса; «%» без значения — «—»; пустые «Зроблено / План» — «—»; карточка без PM — без пустого блока.
- A9. У отчёта «Повернуто» в карточке — строка «Коментар PMO: …».
- A10. «Доступ до картки»: в архиве у всех «Перегляд» (сейчас PM — «Редагування»).
- A11. Сповіщення PMO о рисках (#87: новые высокие, все проблемы, смена статуса) — в прототипе их нет.
- A12. Правка карточки, затронувшая только служебные отметки команды, — не событие «Редагування картки» (в прототипе — пустое событие).
- A13. Строка события без автора — без висящего «·».

**Формы**
- A14. «https://» без адреса — ошибка ссылки.
- A15. Блок погодження PMO не показывается у проекта в архиве; «Повернути» не меняет оценки (в прототипе меняет — ошибка прототипа).
- A16. Смена проекта в форме риска — власник = PM выбранного проекта; в форме отчёта — причина и дата факта очищаются.
- A17. Просмотр отчёта: для не-PMO — «На погодженні з …»; у PM при «Повернуто» — «Новий звіт на основі повернутого»; «Оцінки» в подсказках ИИ — только если есть.

**Шапка, тексты, стили**
- A18. Ошибки прототипа: «gPending» и «kMit» показываются ключами вместо текста.
- A19. Язык прототипа по умолчанию — украинский (сейчас русский).
- A20. Стили приложения для телефона, касаний и узких окон (`overrides.scss`: шапка без переноса, кнопка фильтра 18 px, компактная плашка погодження, нижнее окно меню на телефоне, крупные цели касания, плитки в одну колонку, прилипающая шапка и кнопки панели…) — переносятся в прототип; в `overrides.scss` остаётся только то, что нужно из-за SharePoint (полоса Microsoft 365, выбор людей). Тогда эти правила — из одного источника.
- A21. Состояния «Вмикається…» и ошибка включения «Помічник ШІ» — в меню прототипа (имитация).

## B. Портал исправить — прототип верен (это ошибки или отступления портала)

**Ошибки (видны пользователю)**
- B1. Форма отчёта в EN/RU: «Загальний стан» — по-украински.
- B2. Ссылка с названием, но без адреса — **молча теряется** при сохранении карточки; должна быть ошибка.
- B3. Строка команды с ролью, но без человека — ошибка «роль» вместо того, чтобы пропустить пустую строку.
- B4. Причина изменения показателей сохраняется, даже если показатели вернули обратно (поле уже скрыто).
- B5. Описание проекта, заходи, план дій и тексты отчёта сохраняются с пробелами по краям.
- B6. Власника риска можно оставить пустым.
- B7. Срок заходів у старой записи без даты создания — «не раньше сегодня» вместо «без ограничения».
- B8. «Портфель за напрямами» без проектов — текст другого блока («Проблемних проєктів немає»).
- B9. Имя CSV-файла «archive2-…», «feedback2-…» (внутренний ключ) — должно быть «archive-…», «feedback-…».

**Вид как в прототипе**
- B10. Кнопка закрытия × во всех окнах — значок (сейчас символ шрифта, 18 мест); фокус при открытии окна — на ×.
- B11. «Редагувати проєкт» — со значком карандаша; заголовок формы — «Редагувати проєкт: <назва>».
- B12. Аватары: PM в карточке и вы в меню — крупные (40 px), автор в истории — мелкий (22 px).
- B13. «Історія змін» и сповіщення: «було → стало» — цветные плашки состояния и погодження, суммы «1 450 000 $», даты дд.мм.рррр, пустое — «—» (сейчас простой текст и голое число).
- B14. «Історія станів»: точки 8 px, как в прототипе.
- B15. Подсказка свежести у «Останнє оновлення»; e-mail в подсказке автора отчёта; ссылка без названия — адрес сайта (host), не полный URL; у плитки длинная ссылка обрезается «…»; колонка «Посилання» — через отступ.
- B16. Форма проекта: звёздочка у «Тип», подсказка «· Користувач Microsoft 365» у PM и команды, PM и власник — рядом, даты — в одну строку по три, фокус на новую строку команды / ссылки; порядок проверок как в прототипе.
- B17. Форма риска: в подзаголовке — код проекта; фокус на первое незаполненное поле; ошибки полей не исчезают до исправления (как решено для отчёта, #40) — то же в форме отчёта.
- B18. Форма отчёта при отчёте «на погодженні»: «Зберегти» нажимается и объясняет причину (сейчас просто неактивна).
- B19. Просмотр отчёта: пустой показатель — строка с «—» (сейчас строка пропадает); ошибка погодження без комментария — фокус на поле комментария.
- B20. Счётчик комментариев в списке открывает карточку с раскрытыми комментариями.
- B21. «Головна» без доступных проектов — заголовок и одна карточка «У вас поки немає доступних проєктів» (сейчас пустые блоки и нули); загрузка — заголовок, значок загрузки и «Завантаження…» (сейчас «…»).
- B22. Колокольчик — сразу (сейчас появляется после загрузки, шапка сдвигается); архивная плитка — по фазе проекта, без строки резюме; «← Сповіщення» сохраняет «Лише нові».
- B23. Окно «Призначення» — текущий и новый PM рядом, текущий и новый власник рядом.
- B24. Сортировка по «Погодження» — явный порядок (на погодженні → повернуто → погоджено).

## Этапы

1. **Прототип** (A1–A21) — тесты на прототипе (jsdom) и общие векторы, где правило есть в обоих: порядок «Головної», «Портфель за напрямами», «Доступ до картки» в архиве, сповіщення (векторы `notify.json`), правила форм (новый вектор `project-form.json`: команда без человека, ссылка без адреса, «https://»). 1 день.
2. **Портал: ошибки** (B1–B9) — каждая с тестом, который без исправления падает. 0,5 дня.
3. **Портал: вид** (B10–B24) — тесты рендера. 1 день.
4. **Решения C1–C8** — после ваших ответов. 0,5 дня.
5. **Повторная сверка** — тот же снимок стилей портала и прототипа по всем экранам, плюс телефон (375 px) и тёмная тема; критерий — 0 расхождений, кроме перечисленных ниже. Затем тест, «Довідка» ×3 (если меняется поведение), «Що змінилося», выкладка на тест.

Остаются отличиями (так задумано): выбор людей из Microsoft 365 вместо списка демо-сотрудников; состояния синхронизации SharePoint (проект готовится, отчёт обновляется, проверки свежих данных); вход Microsoft для ИИ; «увійти як інший користувач», демо-данные и подвал прототипа; «Відгуки» только на тестовом сайте.
