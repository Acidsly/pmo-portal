### Задача 3. Команда проекта и ссылки

**Данные:**
- новый список `Lists/ProjectTeam` «Команда проєкту»: `tmProject` (подстановка, запрет удаления проекта), `tmUser` (пользователь, обязательно), `tmRole` (текст, обязательно), `tmTopics` (текст «З яких питань звертатися»), служебный `pmoAcl`;
- `pmLinks` (Note, JSON `[{ "t": "Назва", "u": "https://…" }]`) в «Проєкти».

**Миграция (`Deploy-PMO.ps1`, один раз на проект):** скрытое поле `pmMigrated` (текст, отметки через запятую). Проект без отметки `team` получает строки команды из `pmStakeholders` с ролью «Стейкхолдер» и отметку; без отметки `links` — `pmLinks = [{ "t": "Loop", "u": pmLoop }]` (если `pmLoop` заполнен) и отметку. Повторный запуск проект с отметкой не трогает — удалённые PM строки и ссылки не возвращаются.

**Синхронизация:** стейкхолдеры для прав и «Доступ до картки» — пользователи из команды проекта (`Get-Access`, векторы `acl.json`); `pmStakeholders` синхронизация заполняет из команды (для представлений); `Lists/ProjectTeam` добавляется в цикл прав дочерних элементов (PM правит, остальные читают, архив — чтение).

**Приложение:**
- карточка: «Учасники» — PM, власник и таблица «Команда проєкту» (аватар, имя, должность, роль, з яких питань); блок «Посилання» (список ссылок, открываются в новой вкладке);
- правка карточки (только PM): таблица команды — добавить (выбор человека, роль обязательна, вопросы), изменить, убрать (в корзину сайта); ссылки — добавить, изменить, убрать, проверка `https://`;
- изменения команды и ссылок — в «Історії змін» («Редагування картки»: «+ Ім'я — роль», «− Ім'я»);
- новый проект (PMO): те же блоки;
- плитка и таблица: вместо «Loop» — число ссылок / первая ссылка.

**Приёмка:** существующие стейкхолдеры и Loop перенесены; PM добавляет участника с ролью — через ≤ 15 мин у участника доступ «перегляд і коментарі»; без роли — ошибка; ссылки открываются; история показывает изменения; векторы прав (`acl.json`) — с командой.

### Задача 4. Страница «Відгуки»

**Данные:**

**Синхронизация:** шаг «Відгуки → загальний список» — копия без вложений, обновление по `fpId` только при изменении.

**Приложение:**

- свои отзывы — со скриншотами (из «Відгуки»);
- администратор сайта: у каждой строки — статус и ответ, «Зберегти» (пишет в «Відгуки», в общей таблице — после синхронизации, на экране — сразу), все скриншоты;

### Задача 5. Утверждение статус-отчётов (PMO)

**Принцип:** PMO не правит сам отчёт. Решение PMO — отдельная запись в новом списке, в которой есть только цвета, решение и комментарий, поэтому «меняет только цвета» соблюдается правами SharePoint, а не только интерфейсом.

**Данные:**
- новый список `Lists/ReportApprovals` «Погодження звітів»: `apReport` (подстановка на отчёт), `apDecision` (Choice: Погоджено, Повернуто), `apSchedule` / `apBudget` / `apResources` (Choice RAG, пусто — без изменений), `apNote` (Note, комментарий); автор и дата — стандартные; группе PMO — добавление, остальным — чтение;
- в «Статус-звіти»: `srApproval` (Choice: На погодженні, Погоджено, Повернуто; по умолчанию «На погодженні»; пишет синхронизация), `srApprovedBy`, `srApprovedAt`, `srApprovalNote`; миграция — уже применённые отчёты → «Погоджено».

**Синхронизация (`Invoke-PMOSync.ps1`):**
- новый шаг перед переносом: последняя запись «Погодження» по отчёту → в отчёт: `srApproval`, кто, когда, комментарий; изменённые цвета записываются в оценки отчёта (общий стан пересчитается), журнал — строка «Погодження звіту» с «було → стало» и комментарием; запись «Погодження» после применения — только для чтения;
- перенос в карточку (шаг 1): `$pending` — только `srApplied ≠ так` **и** `srApproval = Погоджено` (плюс прежняя проверка автора = PM);
- права: отчёт после первой синхронизации — только для чтения всем (PM больше не правит отправленный отчёт); строки «Погодження» — чтение участникам проекта.

**Правила (общие векторы `tests/cases/approval.json`, PowerShell и Jest):** что попадает в карточку (только «Погоджено»), какие цвета итоговые (решение PMO поверх PM), общий стан, «Повернуто» — карточка без изменений; комментарий обязателен, если цвета изменены или отчёт возвращён.

**Приложение:**
- наложение (`logic/overlay.ts`): отчёт накладывается на карточку только с решением «Погоджено» (из отчёта или из свежей записи «Погодження», ещё не перенесённой синхронизацией) — PMO видит результат сразу;
- статус-отчёт после отправки — пометка «На погодженні» в карточке, колонка «Погодження» в списке отчётов;
- PMO (участник группы): блок «Очікують погодження» на главной и представление в «Статус-звіти»; в отчёте — «Погодити», «Погодити зі зміною оцінок», «Повернути на доопрацювання» (комментарий);
- PM: «повернуто: коментар» в карточке, кнопка «Новий звіт на основі повернутого».

**Приёмка:** отчёт PM не меняет карточку до утверждения; PMO утверждает со сменой цвета — карточка с новым станом, журнал «було → стало»; возврат — PM видит комментарий, карточка без изменений; попытка PMO изменить сам отчёт — нет прав.

**Позже (не в этом раунде):** уведомление PM о возврате и PMO о новых отчётах — письмом или в Teams (сейчас почта у синхронизации отключена).

### Задача 7. Аналитика на главной

Сначала — новая главная в прототипе (утверждает пользователь), затем приложение. Всё считается по видимым пользователю проектам; суммы бюджета на главную не выносятся. Правила подсчёта — в `logic/` с тестами Jest.

1. **Полоса показателей** (кликабельные, ведут в отфильтрованный список): активні проєкти; частка проєктів зі свіжим звітом (≤ 14 днів); «Очікують погодження» (PMO); високі ризики (відкриті, ≥ 15); прострочені проєкти (план минув, проєкт відкритий).
2. **Карта ризиків 5×5** (ймовірність × вплив): у клітинці — кількість відкритих ризиків, колір за рівнем; клік — ці ризики.
3. **Найбільші зсуви термінів:** топ-5 за різницею «прогноз − план» (дні) і кількість перенесень дати за журналом.
4. **Найближчі запуски (30 днів):** дата запуску, стан, PM.
5. **Портфель за напрямами:** стовпці за напрямами з розбивкою за станом.
6. **«Мої дії» за роллю:** PM — мої проєкти без свіжого звіту, повернуті звіти; PMO — черга погодження, «прийняті» ризики з оцінкою ≥ 15.

**Приёмка:** цифры сходятся с отфильтрованными списками; клики ведут в нужный список; на телефоне — блоки друг под другом; три языка.
