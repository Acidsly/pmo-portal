# Бюджет через статус-звіт: «Бюджет (план)» и «Прогноз витрат на завершення» — план (1.7.7.0)

Цель: деньги ведутся как сроки — плановый бюджет и прогноз меняются только статус-отчётом с причиной и попадают в карточку после погодження PMO. В статус-отчёте — ключевой показатель «Прогноз витрат на завершення» (сколько проект будет стоить к завершению), по образцу «Прогноз завершення» для сроков. Нужен дайджесту (перерасход / экономия заранее) и карточке. Выпуск — после «Країни» (1.7.6.0), ветка `change/forecast-cost` от `main` **только после слияния стран** (не от `change/countries` — конфликты в `Deploy-PMO.ps1`, `defs.tsx`, прототипе).

## Решения (21.10.2026, предложение — подтверждает пользователь)

1. Поля: `srForecastCost` (отчёт, Currency, `LCID='1058' Decimals='0'`, как `srActualCost`) → после погодження PMO синхронизация переносит в `pmForecastCost` (карточка). Ключевое поле эталона (`Get-StateKeys`, после `pmActualCost`); в форме карточки скрыто, как остальные ключевые.
2. **Пусто и 0 — «не задан»** (ревью HIGH-1): `Project.forecastCost: number | null` (как у отчёта), стереть прогноз нельзя (как затраты: пустое значение отчёта не переносится). Форма отчёта, блок «Ключові показники»: поле рядом с «Витрати на дату»; подставляется из карточки (как затраты), пусто — если в карточке не задан. Подсказка под полем: «за темпом витрат: ~$X» = витрати на дату ÷ % виконання × 100 (только при % > 0; `paceForecast` в `logic/status.ts`). **Причина изменения требуется** (решение 21.10: «причину изменений сроков и бюджетов требуем») — `forecastCost` и `budgetPlan` в `KEYS` (`logic/forms.ts:55–57`), `KEYF` прототипа (:2894), `KEY_CHANGE` ИИ (`aiRules.ts:88`), описание `srKeyReason` (`Deploy-PMO.ps1:629`); «Витрати на дату» и % — без причины, как сейчас.
2a. **«Бюджет (план)» — ключевой показатель через отчёт** (решение 21.10): новое поле отчёта `srBudgetPlan` (Currency; `srBudget` — уже оценка «Бюджет», не трогаем) → `pmBudget` после погодження; `pmBudget` — в `Get-StateKeys` (правка в обход отчёта откатывается); в форме карточки бюджет — только при создании проекта (PMO), при правке — показ (`projectEditBody` больше не пишет `pmBudget`, иначе откат; ключ `budget` в `pmEditLog` синхронизация по-прежнему понимает — старые правки не теряются); в форме отчёта — поле «Бюджет (план)» в «Ключові показники», подставляется из карточки. Векторы: `state.json` (`pmBudget` в эталоне; «нет в эталоне — дополнение без отката»), `apply.json` (`budgetPlan`), `report-form.json` (изменение бюджета без причины — ошибка), `card-edit` — правка карточки бюджет не пишет.
3. Проверка **только при сохранении** и только непустого прогноза (> 0): не меньше «Витрат на дату» — ошибка у поля с подсказкой «оновіть прогноз» (затраты могли вырасти выше подставленного прогноза; так же у возвращённого отчёта). Общие векторы `tests/cases/report-form.json` (Jest + прототип): пусто, 0, меньше затрат, возвращённый отчёт со старым прогнозом.
   **«Завершено» / «Скасовано»:** прогноз = «Витрати на дату» и поле закрыто (как % = 100 у «Завершено», `progressLocked`) — отклонение считается по факту.
4. «Історія змін»: изменение прогноза записывается в журнал («Статус-звіт», поле «Прогноз витрат на завершення»; было «—» при первом прогнозе). **Формат суммы — как в интерфейсе портала** (`Bits.tsx` `money`: «1 234 000 $»): `Human` синхронизации и `human` приложения — по общему вектору `tests/cases/money.json` (Test-Scripts + Jest), иначе строки журнала разойдутся (ревью HIGH-3). Дайджест — тот же формат (сейчас в макетах «$81 000» — привести при реализации рассылки). — `$DISPLAY`, `SHOWN` (overlay), диффы прототипа; «Витрати на дату» в журнал по-прежнему не пишутся (не меняем).
5. Карточка: блок «Бюджет» — строка «Прогноз витрат» и отклонение от бюджета («+$25 000 (26%)» красным / «−$4 000» зелёным); «Перегляд звіту» — показатель рядом с затратами; таблица «Проєкти» / «Архів» — колонка «Прогноз витрат» (не в `defaults`).
6. Помощник ИИ: отпечаток отчёта (`aiCheck.ts` `reportPrint`) — обязательно; правило «бюджет зелёный, а прогноз выше бюджета» — предупреждение (`aiRules.ts`, тексты uk/en/ru, прототип); prompt «Чернетка» (`copilot/prompts/draft.md`) — поле и правило оценки. Полный «Набір перевірок» не гоняем (кредиты, см. память) — только затронутые случаи.
7. Существующие проекты: прогноз пустой — дайджест и карточка считают по бюджету (без отклонения) до первого отчёта с прогнозом. Демо-данные теста — прогнозы в `Seed-TestData.ps1`.

## Риски

- Поле не прочитано в `$PROJ` → эталон «пустой» → откат прогноза в каждой синхронизации (этап 2, тест).
- Приложение раньше `deploy` → `$select` с несуществующим полем → проекты / отчёты не читаются (на тесте и проде — сначала `deploy`).
- Ревью плана — Sonnet 21.10: approve with changes; HIGH-1…3 и MEDIUM-4…7 внесены выше.
- Отпечаток ИИ без прогноза → проверка ИИ не сбрасывается при изменении прогноза (этап 4, тест `aiCheck`).
