# Папки проектов, заморозка архива, журнал по требованию

Дата: 2026-09-29 · Ветка: `change/project-folders` (от `main` 5ea0296) · Сложность: средняя (синхронизация, развёртывание, приложение, миграция данных теста)

## Задача

Нагрузка: ~30 активных проектов, к концу года ~40, 2 статус-отчёта в неделю. Сейчас синхронизация выдаёт уникальные права **каждой** дочерней записи
(`Invoke-PMOSync.ps1`, `Set-ItemAcl` для отчётов, рисков, комментариев, журнала, команды, погоджень) — ~500 записей в год на проект.
«Зміни показників» перейдут рекомендованные Microsoft 5 000 уникальных прав на список примерно через 7 месяцев, 50 000 (жёсткий предел) — через 4–5 лет.
Приложение при каждом открытии читает все списки целиком.

## Решения (согласованы с пользователем)

1. **Папка на проект** в шести дочерних списках: `StatusReports`, `RisksIssues`, `ProjectComments`, `KeyChanges`, `ProjectTeam`, `ReportApprovals`.
   Имя папки — `P<ID проекта>` (не код: `pmCode` меняет `Renumber-Projects.ps1`). Права выдаются папке, записи наследуют.
   Уровни — **как сейчас у записей**: отчёты, комментарии, журнал, погодження — чтение всем людям проекта; риски и команда — PM правит, остальные читают;
   PMO — чтение; владельцы сайта — полный доступ; архив — чтение всем. Сама запись проекта в «Проєкти» сохраняет свои права (одна на проект).
2. **Создание записей не меняется**: приложение создаёт запись в корне списка, как сейчас; синхронизация переносит её в папку проекта и сбрасывает личные права.
   Журнал синхронизация пишет сразу в папку. Так приложение не переходит на `AddValidateUpdateItemUsingPath` (строковые значения, региональные форматы дат и чисел).
3. **Заморозка архива**: обычный запуск не пересчитывает доступ архивного проекта, если он уже посчитан после архивации: `pmoAcl` проекта = `arch:<хэш>`
   (префикс не из алфавита хэша 0-9A-F) **и** все шесть папок проекта существуют с непустой отметкой `pmoAcl`. Иначе — полный пересчёт этого проекта.
   Еженедельный пересчёт уже есть — задание `rebuild-permissions` (воскресенье 3:00, `Set-MacSchedule.ps1`), он учитывает и архив.
4. **Журнал по требованию** (только «Зміни показників»): при загрузке приложения — только строки переноса плановой даты (`kcField = pmPlanEnd`, для «Зсуви термінів»
   на главной), полный журнал проекта — при открытии карточки. Экраны не меняются.
5. **Повтор при 429**: все запросы CSOM синхронизации — через `Invoke-PnPQuery -RetryCount` (повтор с паузой по `Retry-After`).

## Проверено на тест-сайте (временный скрытый список `Lists/PmoFolderSpike`)

- Перенос записи в папку (`File.MoveToUsingPath` для `<id>_.000`) сохраняет ID, `Created`, `Modified`, автора, связь с проектом и версии.
- После `ResetRoleInheritance` запись наследует права папки; запись, созданная `Add-PnPListItem -Folder`, наследует сразу.
- `Get-PnPListItem` и REST `GetList(@u)/items` возвращают записи из всех папок **и сами папки** (`FileSystemObjectType` = Folder / 1) — их нужно отбрасывать.
- У папки есть поле `pmoAcl` списка (читается и пишется `SystemUpdate`); папки создаются через API при выключенной кнопке «Нова папка» (`EnableFolderCreation` не нужен).
- Временный список удалить в корзину не удалось (нет разрешения на действие) — остаётся скрытым; убрать вручную (Вміст сайту → PmoFolderSpike → Видалити) или оставить.

## Риски

- **Окно до синхронизации (было и раньше):** новая запись в корне наследует права списка — её видят все участники сайта до ближайшей синхронизации (≤15 мин).
  Не ухудшается; закрыть можно отдельно (создание сразу в папке через `AddValidateUpdateItemUsingPath`). Технический долг.
- Сбой посреди миграции: каждая запись переносится и сбрасывается независимо, повторный запуск продолжает (перенос идемпотентен — запись уже в папке пропускается).
- Старое приложение увидит папки строками (пустые ссылки на проект → строки отбрасываются экранами, в худшем случае ошибка в консоли) — поэтому приложение
  ставится до синхронизации; на проде между установкой приложения и миграцией — пауза, чтобы открытые вкладки обновились.
- Первая миграция на проде: ~1 пакетный запрос на ~20 записей; время оценивается по тесту (этап 8, п. 5).
- Прод: тот же порядок (этап 8, пп. 2–5) — отдельным «да».
