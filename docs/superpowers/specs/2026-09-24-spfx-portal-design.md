# Портфель проєктів — приложение SPFx по прототипу

Дата: 2026-09-24. Статус: на согласовании.

## Зачем

Стандартные списки и JSON-форматирование SharePoint не позволяют повторить прототип (`prototype/pmo-prototype.html`): нет своей шапки и тем, карточки проекта с историей, формы отчёта с подстановкой и живым расчётом, таблиц с выбором колонок. Приложение SPFx (React) воспроизводит прототип 1:1 и работает с теми же списками.

## Решения (согласованы 2026-09-24)

| Вопрос | Решение |
|---|---|
| Где работает | Главная сайта — страница приложения на весь экран (SharePoint «страница приложения из одной веб-части»), и личное приложение / вкладка в Teams. Стандартные списки остаются для администраторов и выгрузок |
| Отчёт → карточка | Приложение **сразу** показывает новые показатели: накладывает на карточку ещё не применённые отчёты по тем же правилам, что синхронизация. В списки пишет только синхронизация (`Invoke-PMOSync.ps1`): права не расширяются, журнал ведётся одним механизмом |
| Язык | По умолчанию — язык профиля Microsoft 365 (`uk` / `en` / `ru`, иначе `uk`); переключатель UA/EN/RU в шапке, выбор запоминается в браузере |
| Код проекта | Если пусто — следующий `PRJ-###` (максимальный номер `PRJ-` + 1); можно ввести свой |
| Тема | Светлая / тёмная, как в прототипе; по умолчанию — системная; выбор запоминается в браузере |

## Что берётся из прототипа без изменений

Экраны, порядок блоков, колонки, тексты (словари `T` и `FLD`, строки 506–665), CSS-переменные и размеры (строки 10–462), правила: общий стан — худшая из трёх оценок; свежесть отчёта — >14 дней красный, >8 жёлтый; отклонение прогноза; освоение бюджета >100 красный, >90 жёлтый; оценка риска ≥15 красный, ≥8 жёлтый; сортировка по умолчанию — стратегические, приоритет, название; срезы динамики — 7 точек через 14 дней, последний отчёт на дату среза, архивный проект — до даты архивации.

Не переносится (только демо): «войти как другой пользователь», справочник `ORG`, демо-данные и кнопки их загрузки, индикатор источника данных, `window.claude` / хранение в одном документе.

## Архитектура

```
spfx/                              решение SPFx 1.23.2 (Heft), Node 22, React 17.0.1, TypeScript
  src/webparts/pmoPortal/
    PmoPortalWebPart.ts            точка входа: контекст SPFx -> React
    logic/        чистые функции без SharePoint: rag, dates, freshness, status, overlay, dynamics, access, sort
    data/         типы модели, сопоставление REST <-> модель (map*.ts), репозиторий SharePoint (SpRepo.ts)
    i18n/         словари из прототипа (uk/en/ru), useI18n
    theme/        CSS-переменные светлой и тёмной темы, useTheme
    components/   шапка, кнопки, таблица, панель, аватар, пилюли, графики
    pages/        Home, Projects, Reports, Risks, Archive
    panels/       ProjectCard, ReportForm, ProjectForm, RiskForm
tests/cases/                       общие тест-векторы (JSON) — их читают и Jest, и tests/Test-Scripts.ps1
scripts/Deploy-App.ps1             сборка .sppkg -> каталог приложений -> страница приложения
```

- **Данные:** REST SharePoint (`SPHttpClient` из SPFx) от имени пользователя — видны только проекты, которые ему открыла синхронизация. Списки: `Lists/Projects`, `Lists/StatusReports`, `Lists/RisksIssues`, `Lists/ProjectComments`, `Lists/KeyChanges`. Внутренние имена полей — как в `CLAUDE.md` («Модель данных»).
- **Права в интерфейсе:** кнопки редактирования показываются по фактическим правам элемента (`EffectiveBasePermissions`), а не по вычислению иерархии: права уже выдала синхронизация.
- **Доступ к карточке** («кто и с каким правом»): синхронизация, которая знает цепочку руководителей, записывает список в скрытое поле проекта в формате JSON; приложение его показывает. Graph из браузера не нужен — дополнительных разрешений не требуется.
- **Должность и почта людей** — из профиля SharePoint (`SP.UserProfiles.PeopleManager`) по мере показа, с кэшем в памяти.
- **Наложение отчётов:** `logic/overlay.ts` повторяет шаг 1 синхронизации (`MAP`, «Завершено» → «Архівний», самый свежий отчёт задаёт стан, дату и «Останній апдейт»). Общие тест-векторы гарантируют, что PowerShell и TypeScript считают одинаково.
- **Запись:** приложение создаёт статус-отчёты, риски, комментарии и проекты и редактирует карточку (без ключевых показателей) от имени пользователя. Журнал «Зміни показників», перенос отчёта в карточку, права, показатели портфеля — синхронизация. Отчёт, созданный приложением, помечен как неприменённый (`srApplied` = нет), как и созданный через форму SharePoint.
- **Главная** считает кольцо и динамику по видимым пользователю проектам (как прототип), а не по служебному списку «Показники портфеля» — тот остаётся для стандартной страницы.

## Этапы

| Этап | Результат | Проверка |
|---|---|---|
| 1. Каркас и главная | Node 22, решение SPFx, логика с тестами, слой данных (чтение), шапка с вкладками, языком и темой, главная 1:1 с прототипом, установка на `pmo-test` страницей приложения на весь экран | Jest + `Test-Scripts.ps1`; главная на `pmo-test` рядом с прототипом в Chrome |
| 2. Проекты и карточка | Таблица (сортировка, фильтры, колонки, представления), плитки, архив, отчёты и риски списками, карточка проекта (все разделы, только чтение) | То же |
| 3. Формы и запись | Новый проект / редактирование, статус-отчёт (подстановка, живой стан, причина), риск, комментарии, проверки прав | То же + сценарии из `CLAUDE.md` («Как проверять изменения прототипа») |
| 4. Teams и прод | Пакет для Teams, синхронизация пишет доступ в JSON, выпуск в каталог тенанта и на `/sites/pmo` после подтверждения | Teams на тестовом сайте; прод — только после «да» |

У каждого этапа — свой план в `docs/superpowers/plans/`. План этапа 2+ пишется после приёмки предыдущего.

## Ограничения и риски

- Над приложением остаётся полоса Microsoft 365 (поиск, профиль) — её SharePoint не скрывает. В Teams её нет.
- Размещённый (hosted) workbench снимается 2026-12-01 — отладка через страницу `pmo-test` с `?debug=true&noredir=true&debugManifestsFile=https://localhost:4321/temp/build/manifests.js`.
- Каталог приложений сайта `pmo-test` создаётся один раз правами администратора SharePoint; выпуск в каталог тенанта (`smarthrua.sharepoint.com/sites/appcatalog`) и на прод — только с подтверждения пользователя.
- Задержка записи до одного интервала синхронизации (10–15 мин) для журнала и прав; на экране изменения видны сразу.
