# Портфель проєктів — техническое задание

Версия ТЗ: 2026-09-25. Эталон интерфейса — прототип [`prototype/pmo-prototype.html`](../prototype/pmo-prototype.html) (описание — [PROTOTYPE.md](PROTOTYPE.md)).
Если текст ТЗ и прототип расходятся, решает прототип, кроме пунктов, явно помеченных «отличие от прототипа».

## 1. Назначение

Единое место, где компания ведёт портфель проектов:
- у каждого проекта — карточка: участники, сроки, бюджет, состояние, история изменений;
- PM регулярно сдаёт статус-отчёт — только через него меняются ключевые показатели проекта;
- риски и проблемы проекта с оценкой «вероятность × влияние»;
- руководство видит состояние портфеля на главной: сводку, динамику, проблемные проекты, запросы на решение;
- каждый видит только те проекты, в которых участвует он сам или его подчинённые.

## 2. Пользователи и роли

| Роль | Кто | Видит | Может |
|---|---|---|---|
| PM | ответственный за проект (поле «PM») | свой проект | править карточку, сдавать статус-отчёты, вести риски, комментировать |
| Руководители PM | цепочка руководителей PM по полю Manager в Entra ID (руководитель PM-ов, CIO, CEO…) | проекты подчинённых | смотреть и комментировать |
| Власник (собственник) | заказчик проекта | проект | смотреть и комментировать |
| Стейкхолдери | несколько человек | проект | смотреть и комментировать |
| Руководители собственника и стейкхолдеров | цепочки в Entra ID | проекты, где роль у них или у подчинённых | смотреть и комментировать |
| `PMO-адміністратори` | офис управления проектами | все проекты | заводить новые проекты и назначать PM; остальное — смотреть и комментировать |
| Владельцы сайта | администраторы портала | всё | полный доступ SharePoint |
| Остальные сотрудники | участники сайта | пустой портал | — |

Пример: CEO видит всё, потому что CIO — его подчинённый; CIO видит всё, потому что руководитель PM-ов — его подчинённый; финансовый директор видит только проекты, где роль у него или у его подчинённых. Проект в архиве — только просмотр для всех, включая PM.

## 3. Где работает

- **SharePoint Online**, сайт-коммуникация `/sites/pmo` (тестовый — `/sites/pmo-test`). Главная страница — приложение SPFx на весь экран (страница приложения из одной веб-части).
- **Microsoft Teams** — то же приложение как личное приложение / вкладка (этап 4).
- Стандартные списки SharePoint остаются: для администраторов, выгрузок в Excel и Power BI.

## 4. Модель данных

Внутренние имена полей не переименовываются никогда; меняются только отображаемые названия (uk / en / ru).

### 4.1. Проєкти (`Lists/Projects`)

| Поле | Имя | Тип | Правка |
|---|---|---|---|
| Назва проєкту | `Title` | текст, обязательно | карточка |
| Код | `pmCode` | текст; пусто → следующий `PRJ-###` | карточка |
| Напрям | `pmDepartment` | выбор: ІТ, HR та кадрове адміністрування, Розрахунок зарплати, Продажі, Фінанси, Операції, Юридичний | карточка |
| Посилання | `pmLinks` | скрытое многострочное: JSON `[{"t": назва, "u": https://…}]` | карточка (блок «Посилання») |
| Посилання на Loop (прежнее) | `pmLoop` | ссылка; при развёртывании переносится в `pmLinks`, дальше не заполняется | — |
| Тип | `pmType` | Стратегічний / Звичайний | при создании, дальше — отчёт |
| Пріоритет | `pmPriority` | 1 — Високий / 2 — Середній / 3 — Низький | карточка |
| PM | `pmManager` | пользователь, обязательно | карточка |
| Власник | `pmOwner` | пользователь | карточка |
| Стейкхолдери | `pmStakeholders` | несколько пользователей; повторяет людей «Команда проєкту» | синхронизация |
| Статус | `pmStatus` | Ініціація, Планування, Реалізація, Призупинено, Архівний («Скасовано» — только у прежних проектов, миграция переводит в «Архівний») | при создании, дальше — отчёт |
| Загальний стан | `pmRAG` | Зелений / Жовтий / Червоний | только отчёт |
| % виконання | `pmProgress` | 0–100 | только отчёт |
| Дата старту / запуску (продакшн) / завершення (план) | `pmStart`, `pmGoLive`, `pmPlanEnd` | дата | при создании, дальше — отчёт |
| Прогноз завершення | `pmForecastEnd` | дата | только отчёт |
| Дата архівації | `pmArchivedAt` | дата | синхронизация |
| Бюджет (план) / Фактичні витрати | `pmBudget`, `pmActualCost` | деньги, ₴ | бюджет — карточка; факт — отчёт |
| Останній статус-звіт / Останній апдейт | `pmLastReport`, `pmLastUpdate` | дата / текст | синхронизация |
| Останній коментар | `pmLastComment` | текст | синхронизация |
| Опис | `pmDescription` | многострочный | карточка |
| служебные | `pmoAcl` (хэш выданных прав), `pmEditLog` (правки карточки до переноса в журнал), `pmAccess` («Доступ до картки», JSON), `pmMigrated` (отметки миграций раунда 2: `team`, `links`) | скрыты | приложение / синхронизация / развёртывание |

### 4.2. Статус-звіти (`Lists/StatusReports`)

Проект, дата отчёта, период (Тиждень, 2 тижні, Місяць, Квартал); три оценки — терміни `srSchedule`, бюджет `srBudget`, ресурси `srResources`; вычисляемое общее состояние `srRAG`; новые значения ключевых показателей (`srStatus`, `srType`, `srProgress`, `srStart`, `srGoLive`, `srPlanEnd`, `srForecastEnd`, `srActualCost`) и причина их изменения `srKeyReason`; резюме одной строкой `Title`; зроблено / план / проблеми (`srDone`, `srNext`, `srIssues`); «Потрібне рішення керівництва» `srDecision` и текст решения `srDecisionText`; копии типа и приоритета проекта; погодження PMO — `srApproval` (На погодженні, Погоджено, Повернуто), `srApprovedBy`, `srApprovedAt`, `srApprovalNote` (пишет синхронизация из «Погодження звітів»); служебные `srApplied` (перенесён ли в карточку), `pmoAcl`. В статусе отчёта есть дополнительное значение «Завершено» — оно отправляет проект в архив. При развёртывании уже применённые отчёты получили «Погоджено».

### 4.3. Ризики та проблеми (`Lists/RisksIssues`)

Проект, опис `Title`, тип (Ризик / Проблема), ймовірність 1–5, вплив 1–5, вычисляемая оцінка = P × I, власник ризику, статус (Відкрито, В роботі, Закрито), термін виконання заходів `riDue`, стратегія реагування `riStrategy` (Уникнення, Зниження (пом'якшення), Передача, Прийняття; можно не выбирать), заходи для зниження ризику `riMitigation`, план дій у разі настання `riContingency`, копии типа и приоритета проекта.

### 4.4. Служебные списки

- **Зміни показників** (`Lists/KeyChanges`) — журнал: проект, дата, кто изменил, вид изменения (Створення, Статус-звіт, Редагування картки, Погодження звіту), поле, було, стало, причина. Пользователям — только чтение.
- **Коментарі** (`Lists/ProjectComments`) — проект и текст; автор и дата — стандартные поля.
- **Команда проєкту** (`Lists/ProjectTeam`) — проект `tmProject`, учасник `tmUser` (обязательно), роль у проєкті `tmRole` (текст, обязательно), з яких питань звертатися `tmTopics`. Люди команды — стейкхолдеры проекта (просмотр и комментарии). Строки заводит и убирает PM из формы карточки (убранная строка — в корзину сайта). При развёртывании прежние стейкхолдеры перенесены строками с ролью «Стейкхолдер».
- **Погодження звітів** (`Lists/ReportApprovals`) — решение PMO по статус-отчёту: `apReport`, `apProject`, `apDecision` (Погоджено / Повернуто), изменённые оценки `apSchedule` / `apBudget` / `apResources` (пусто — без изменений), комментарий `apNote`, служебное `apApplied`. Добавляет только группа PMO; сам отчёт PMO не правит.
- **Відгуки** (`Lists/Feedback`, только тест) — отзывы со скриншотами-вложениями; статус (Новий, Прийнято, Зроблено, Прокоментовано, Відхилено) и ответ ставят владельцы сайта; **Відгуки — загальні** (`Lists/FeedbackPublic`) — копия без скриншотов для страницы «Відгуки» (видят все), пишет синхронизация.

Дочерние списки связаны с проектом подстановкой с запретом удаления.

## 5. Бизнес-правила

1. **Ключевые показатели** — статус, общее состояние, тип, % выполнения, все даты, фактические затраты — меняются только через статус-отчёт. В форме карточки их нет (при создании проекта тип, статус и даты задаются).
2. **Общее состояние отчёта** — худшая из трёх оценок: хотя бы одна красная → Червоний; иначе хотя бы одна жёлтая → Жовтий; иначе Зелений. Вручную не выбирается. Состояние проекта = состояние самого свежего по дате отчёта.
3. **Перенос отчёта в карточку.** Только отчёт, **погоджений PMO**, переносит в проект заполненные ключевые показатели (оценки — с учётом изменений PMO). Самый свежий отчёт задаёт ещё общее состояние, дату последнего отчёта и «Останній апдейт» (резюме). Отчёт помечается применённым.
3a. **Погодження PMO.** Новый отчёт — «На погодженні». PMO (группа `PMO-адміністратори`) погоджує его как есть, погоджує со сменой оценок (терміни, бюджет, ресурси) или повертає на доопрацювання; смена оценки и возврат — только с комментарием; решённый отчёт повторно не решается; PMO, выбравший тот же цвет, ничего не меняет. Возврат — карточка без изменений, PM видит комментарий и может завести новый отчёт на основе возвращённого. Решение — строки журнала «Погодження звіту» («було → стало» оценок или «На погодженні → Погоджено / Повернуто», комментарий). Общие векторы `tests/cases/approval.json`.
4. **Причина обязательна**, если отчёт меняет статус, тип или любую дату. Она попадает в журнал.
5. **Завершение и отмена.** Статус «Завершено» или «Скасовано» в отчёте → проект получает «Архівний» и дату архивации, уходит в «Архів», становится только для чтения.
6. **Журнал.** Каждое изменённое поле — строка «було → стало», кто, когда, причина. Создание проекта — строка «Створення». Правка карточки — «Редагування картки» (команда — «Ім'я — роль; …», ссылки — названия). Решение PMO — «Погодження звіту».
6a. **Смена статуса проекта** — только статус-отчётом: PM выбирает новый статус в «Ключові показники» и пишет причину → PMO погоджує → статус в карточке и журнале; «Завершено» → архив. Отдельной кнопки нет.
7. **Свежесть отчёта:** до 8 дней — зелёный, 8–14 — жёлтый, больше 14 — красный, нет отчётов — серый.
8. **Просрочка:** дата завершения (план) раньше сегодняшней у активного проекта — красным.
9. **Отклонение прогноза** — разница «прогноз − план» в днях, красным при сдвиге вправо.
10. **Освоение бюджета** = факт / план: больше 90% — жёлтый, больше 100% — красный.
11. **Оценка риска** = вероятность × влияние: 15–25 высокий (красный), 8–14 средний (жёлтый), 1–7 низкий (зелёный). Шкалы:

    | Балл | Ймовірність | Вплив |
    |---|---|---|
    | 1 | рідко, до 10% | незначний: не влияет на сроки и бюджет |
    | 2 | малоймовірно, 10–30% | помірний: отклонение в пределах резерва |
    | 3 | можливо, 30–60% | суттєвий: сдвиг этапа или перерасход до 10% |
    | 4 | ймовірно, 60–90% | значний: сдвиг запуска или перерасход более 10% |
    | 5 | майже напевно, более 90% | критичний: срыв целей проекта |

12. **Активный проект** — любой статус, кроме «Скасовано», «Архівний», «Завершено».
13. **Номер (код) проекта** — только автоматический: `PRJ-` + (максимальный номер среди `PRJ-###` + 1), три цифры; в форме поле только для чтения. Уникальность — поле списка (EnforceUniqueValues); если номер успел занять другой PMO, форма берёт следующий. Единая нумерация существующих проектов — `Renumber-Projects.ps1` (`Invoke-Env -Action renumber`, по порядку создания, с журналом «було → стало»).
14. **Порядок колонок** во всех таблицах: стратегический (щит с мечом; заголовок — иконка компаса), приоритет (стрелки ⏫ ＝ ⏬; заголовок — флажок), название, остальные.
15. **Сортировка по умолчанию** (отличие от прототипа, по итогам приёмки): новые записи сверху — проекты и риски по дате создания, статус-отчёты по дате отчёта, затем по созданию. Любую колонку можно отсортировать щелчком по заголовку.
16. Группировок по статусам нет.
17. **Аналитика главной** (по видимым проектам без архива, без сумм бюджета): активні; частка зі свіжим звітом (≤ 14 днів) среди активных; очікують погодження (PMO); високі ризики — открытые с оценкой ≥ 15; прострочені — план минул у активного; карта ризиків 5 × 5 — открытые риски по ймовірності × впливу; зсуви термінів — активные с прогнозом позже плана, топ-3 по дням, «перенесень» — строки журнала с изменением `pmPlanEnd`; запуски — активные с датой запуска от сегодня до +7 дней (неделя); портфель за напрямами — активные по направлению и состоянию. Блока «Мої дії» нет (решение пользователя): очередь погодження — показатель «Очікують погодження» и «Відображати: Очікують погодження», возвращённый отчёт — заметка в карточке.

## 6. Интерфейс

Общие элементы (см. [PROTOTYPE.md](PROTOTYPE.md)):
- **Шапка:** логотип и название «Портфель проєктів», вкладки Головна · Проєкти · Статус-звіти · Ризики та проблеми · Архів · Відгуки (на тесте), кнопка «?» (инструкция; отзыв — на вкладке «Відгуки» → «Залишити відгук»; колонка «Екран» — понятное название экрана или «Лист PMO» для отзыва из письма), переключатель языка UA / EN / RU, светлая / тёмная тема, аватар текущего пользователя.
- **Язык** по умолчанию — язык профиля Microsoft 365 (uk / en / ru, иначе uk); выбор запоминается в браузере. Значения выбора (статусы, состояния, типы, приоритеты, направления, периоды, статусы рисков) и названия представлений хранятся на украинском, а на экране показываются на языке интерфейса (словарь `i18n/values.ts`); содержимое записей не переводится.
- **Тема** по умолчанию — системная; выбор запоминается.
- **Адрес** `#вкладка/представление/id/форма` открывает нужную вкладку, представление, карточку или форму — ссылку можно переслать.
- **Панель** справа: карточка проекта и все формы; закрывается крестиком, Esc или щелчком по фону.
- **Уведомление** (toast) после сохранения.

### 6.1. Головна

- заголовок «Панель проєктів», «Доступно вам проєктів: N», кнопка «Новий проєкт»;
- полоса показателей (правило 17): каждый показатель открывает отфильтрованный список («Відображати»: Усі проєкти, Немає свіжого звіту, Очікують погодження, Високі ризики, Прострочені);
- «Портфель за станом» — кольцо по общему состоянию активных проектов с числом в центре и легендой (зелений, жовтий, червоний, не оцінено);
- «Динаміка стану портфеля» — столбцы с разбивкой по цвету, 7 срезов через 14 дней до сегодня; на дату среза берётся последний отчёт проекта, архивный проект учитывается до даты архивации;
- «Динаміка»: на каждую дату среза — каждый проект, который уже был создан, не отменён и не ушёл в архив, по последнему погодженому отчёту; без отчёта — серый «не оцінено»; последний срез совпадает с кольцом «Портфель за станом»; блок «Відкриті ризики» — шесть самых высоких, под таблицей «Показано N з M»;
- «Карта ризиків» (щелчок по клетке — её риски под картой) и «Портфель за напрямами» (полосы по состоянию, в каждом цвете — число проектов); «Найбільші зсуви термінів» и «Запуски в найближчі 7 днів»;
- блоки во всю ширину, каждый со ссылкой «Показати все»: «Проблемні проєкти» (жёлтые и красные), «Немає свіжого статус-звіту» (больше 14 дней или нет отчётов), «Потребують рішення керівництва», «Відкриті ризики».

Всё считается по проектам, видимым пользователю.

### 6.2. Проєкти

- выбор «Відображати»: Усі проєкти, Стратегічні, Проблемні, Мої проєкти (я PM, власник или в команде), Немає свіжого звіту, Прострочені;
- режимы «Плитки» и «Список»;
- плитка: код, щит стратегического проекта, состояние плашкой, название, статус и % с полосой, «Останній апдейт» со светофором свежести, первая ссылка из «Посилання» (+N), PM;
- таблица: выбор колонок (шестерёнка), сортировка и фильтр (воронка) по каждой колонке, кнопка «CSV» — выгрузка таблицы как на экране (видимые колонки, фильтры, сортировка; разделитель «;», UTF-8), счётчик «Показано N з M»;
- колонки: стратегічний, пріоритет, назва, код, тип, PM, власник, стейкхолдери, статус, стан, дата звіту, давність звіту, % виконання, дати старту / запуску / плану / прогнозу, відхилення, бюджет, факт, освоєння, останній апдейт, останній коментар, автор коментаря, напрям, посилання, дата архівації;
- подсказка о красной дате и светофоре отчёта.

### 6.3. Статус-звіти

«Відображати»: «Усі звіти», «Потребують рішення», «Очікують погодження»; кнопка «Новий статус-звіт»; колонки: стратегічний, пріоритет, проект, код, дата, період, стан, три оценки, резюме (открывает отчёт), зроблено, план, проблеми, %, статус, автор, погодження, «Потрібне рішення» (при наведении — текст решения), текст рішення.

**Отчёт** (панель): проект, дата, период, стан, погодження; оценки и ключевые показатели, которые отчёт меняет, причина; зроблено / план / проблеми / рішення; «Рішення PMO» — кто, когда, комментарий; для возвращённого — «Новий звіт на основі повернутого» (PM). Для PMO у отчёта «На погодженні» — блок «Погодження звіту»: три оценки (заполнены оценками PM), «Коментар PMO», кнопки «Погодити» / «Погодити зі зміною оцінок» (если оценка изменена) и «Повернути на доопрацювання».

### 6.4. Ризики та проблеми

«Відображати»: «Відкриті» (не закрытые), «Високі ризики» (открытые, оценка ≥ 15) и «Усі елементи»; кнопка «Новий ризик»; колонки: проект, пріоритет, стратегічний, код, опис, тип, оцінка (цветная плашка), ймовірність, вплив, стратегія реагування, власник, статус, термін виконання заходів (красный, если прошёл у открытого риска), заходи, план дій у разі настання. Подсказка «Оцінка = ймовірність × вплив».

### 6.5. Архів

Проекты в статусе «Архівний» с датой архивации (новые архивации сверху); карточка — только просмотр. Навигация как в «Проєкти»: «Список» / «Плитки» (на плитке — дата архивации), «Відображати»: Усі проєкти, Стратегічні, Мої проєкти; CSV, выбор колонок.

### 6.6. Карточка проекта

Сверху: код, список, название; плашки — тип, состояние, статус, приоритет; под ними блок «Посилання» (все ссылки проекта); кнопки «Додати статус-звіт», «Редагувати» (если есть право), иначе замок «Змінювати проєкт можуть PM, власник, керівники PM і PMO…».

Разделы:
0. Заметки погодження: «Статус-звіт від … на погодженні PMO — картка оновиться після погодження»; «Звіт від … повернуто на доопрацювання: комментарий» и для PM кнопка «Новий звіт на основі повернутого».
1. **Учасники** — PM крупно (должность, почта), власник; **Команда проєкту** — таблица: учасник, роль, з яких питань звертатися.
2. **Терміни** — старт, запуск, план, прогноз с отклонением в днях.
3. **Бюджет і виконання** — % с полосой, последний отчёт со светофором, бюджет, факт, освоение.
4. **Історія змін** — последние 3 события, «Показати всю історію (N)»: кто, когда, вид («Оновлено статус-звітом», «Редагування картки», «Створення»), поля «було → стало», причина и резюме отчёта. Сохранённый только что отчёт и правка карточки видны сразу, до синхронизации.
5. **Коментарі** — лента и форма «Додати коментар».
6. **Історія станів** — матрица по последним 8 отчётам: общий стан, терміни, бюджет, ресурси, %.
7. **Статус-звіти** — отчёты проекта: дата, стан, погодження, резюме (дата и резюме открывают отчёт), зроблено / план / проблеми, «Потрібне рішення», комментарий PMO у возвращённого.
8. **Ризики та проблеми** — риски проекта с оценкой; «Додати ризик».

### 6.7. Формы

**Новий проєкт / Редагування.** Новый проект заводит только PMO (у остальных кнопки нет); править — только PM. Разделы «Загальне», «Учасники», «Терміни» (только при создании), «Бюджет і виконання». Обязательны название и PM; PM нового проекта не подставляется — его выбирает PMO (иначе PMO случайно становится PM). Enter в поле выбора людей выбирает человека и не сохраняет форму. Номер — только для чтения, подсказка «Буде присвоєно автоматично». При правке — заметка, что доступ пересчитается. Правка сохраняет «було → стало» для журнала. **Команда проєкту** — строки «учасник, роль (обязательно), з яких питань звертатися», «+ Додати учасника», × — убрать; человек в команде один раз. **Посилання** — строки «назва, адреса» (`https://`, пустое название → «Посилання»), «+ Додати посилання», ×. Ошибки: «Вкажіть роль для кожного учасника команди», «Посилання має починатися з https://».

**Статус-звіт.** Сохранённый отчёт — «На погодженні», уведомление «Звіт надіслано на погодження PMO»; «на основе возвращённого» — форма заполнена данными возвращённого отчёта. Проект (только активные, где есть право), дата (сегодня), период; три оценки обязательны; «Загальний стан (розраховується)» пересчитывается на лету; блок «Ключові показники» заранее заполнен текущими значениями проекта — статус (+ «Завершено → в архів»), %, тип, четыре даты, фактичні витрати; при изменении статуса, типа или дат появляется обязательное «Причина зміни»; резюме одной строкой (обязательно), зроблено, план, проблеми, флажок «Потрібне рішення керівництва» и текст решения.

Сообщения об ошибках: «Оцініть терміни, бюджет і ресурси», «Заповніть резюме одним рядком», «Вкажіть дату звіту», «Вкажіть причину зміни», «Вкажіть назву проєкту», «Оберіть відповідального PM».

**Ризик.** Проект (фиксирован, если открыт из карточки), опис (обязательно), тип, шкалы 1–5 с описанием балла, живая оценка «15 Високий = 3 × 5», стратегія реагування (повторный щелчок снимает выбор), власник ризику (по умолчанию PM), статус, термін виконання заходів (по умолчанию пусто), заходи для зниження ризику, план дій у разі настання. Без права — просмотр с замком.

**Коментар.** Текст обязателен.

Выбор людей — поиск по каталогу пользователей (имя, должность).

## 7. Права доступа

Права выдаёт синхронизация на проект и все его записи (отчёты, риски, команда, погодження, комментарии, журнал):

| Кто | Проект, отчёты, риски | Комментарии и журнал |
|---|---|---|
| PM | редактирование | чтение, добавление комментариев |
| Руководители PM, собственник, команда проекта, руководители собственника и команды | просмотр | то же |
| `PMO-адміністратори` | просмотр всех проектов | то же |
| Владельцы сайта | полный доступ | полный доступ |

Архивный проект — всем просмотр. Права списков: «Проєкти» — участникам сайта чтение, PMO — добавление (новые проекты); «Статус-звіти», «Ризики», «Коментарі», «Команда проєкту» — участникам добавление; журнал — только чтение; «Погодження звітів» — PMO добавление, остальным чтение. Решение PMO синхронизация принимает, только если его автор в группе PMO (или владелец сайта). Статус-отчёт меняет карточку, только если его автор — PM проекта (или владелец сайта); иначе синхронизация его не применяет и пишет предупреждение.

Каждого, у кого есть права хотя бы на один проект (PM, власник, команда, их руководители по цепочке Entra ID), синхронизация добавляет в «Учасники сайту» — иначе портал для него не откроется («Вам нужен доступ»); из группы синхронизация никого не убирает.

Синхронизация записывает список «кто и с каким правом» в скрытое поле `pmAccess` (JSON), приложение показывает его разделом «Доступ до картки». Одинаковость правил проверяют векторы `tests/cases/acl.json`.

Статус-отчёт после первой синхронизации — только для чтения всем, включая PM и PMO: отправленный отчёт не переписывается, PMO решает отдельной записью «Погодження звітів» (тоже только чтение после синхронизации).

### Изменения только через приложение

Участники сайта работают только в приложении, стандартный интерфейс SharePoint для них закрыт настолько, насколько позволяет SharePoint:
- уровень участников сайта — «Участь» (а не «Редагування»): нельзя создавать и удалять списки, менять колонки, представления и страницы;
- страницы и файлы сайта — только чтение;
- списки портала скрыты из «Вміст сайту» и меню, меню сайта SharePoint выключено;
- приложение прячет шапку сайта, панель команд («Редагувати») и левую панель SharePoint у всех, кроме администраторов сайта (право «Керування веб-сайтом»); полоса Microsoft 365 сверху остаётся;
- права выдаёт синхронизация (правка — только PM): записи проекта и папке проекта `P<ID>` в каждом дочернем списке, записи папки наследуют её права; отчёты, комментарии, журнал и погодження — только чтение.

Ограничение платформы: приложение пишет от имени пользователя, поэтому то же самое пользователь технически может сделать, открыв список по прямому адресу, — но только в пределах своих прав (PM — в своём проекте). Полностью без интерфейса SharePoint портал работает в Microsoft Teams.

Права пересчитываются, только если изменился круг участников (сравнение по хэшу в `pmoAcl` проекта и папок); архивный проект после выдачи прав архива обычным запуском не пересчитывается; раз в неделю — полный пересчёт (и архива), чтобы учесть смену руководителей. Приложение при загрузке читает из журнала только переносы плановой даты (главная), весь журнал проекта — при открытии карточки. Приложение показывает кнопки правки по фактическим правам элемента, само прав не вычисляет.

## 8. Разделение ответственности

| Кто | Что пишет |
|---|---|
| Приложение SPFx (от имени пользователя) | новые проекты; правку карточки без ключевых показателей + `pmEditLog` и `pmLinks`; строки «Команда проєкту»; статус-отчёты (`srApplied = нет`); решения PMO («Погодження звітів»); риски; комментарии; отзывы |
| Синхронизация `Invoke-PMOSync.ps1` (по расписанию, раз в 10–15 минут) | решения PMO → отчёт (`srApproval`, оценки); перенос погодженого отчёта в карточку, архив, журнал, последний комментарий, копии типа и приоритета, `pmStakeholders` из команды, права, `pmAccess`, общий список отзывов, напоминания PM |

На экране результат сохранения виден сразу: приложение накладывает неприменённые погоджені отчёты (и свежие решения PMO) на карточку по тем же правилам, что и синхронизация. В стандартных списках изменения появляются после ближайшей синхронизации. Одинаковость правил в PowerShell и TypeScript проверяют общие тест-векторы `tests/cases/*.json`.

## 9. Напоминания

По ключу `-SendReminders` (раз в неделю): каждому PM одно письмо со списком его активных проектов без отчёта дольше `-ReminderDays` дней (по умолчанию 7). Сейчас не включены.

## 10. Нефункциональные требования

- Три языка интерфейса; светлая и тёмная темы; адаптивная вёрстка.
- Данные — только в списках SharePoint сайта; внешних сервисов и баз нет.
- Приложение работает от имени пользователя: видит только то, что ему открыто.
- Скрипты идемпотентны: повторный запуск ничего не дублирует. Данные не теряются: удаление или смена типа поля — только миграцией с переносом значений.
- Прод обновляется только после явного подтверждения.

## 12. Сценарии приёмки

1. Новый проект без кода → получает `PRJ-###`, PM — я, появляется первым в «Проєкти».
2. Правка карточки (приоритет) → в «Історії змін» сразу «Редагування картки: 2 — Середній → 1 — Високий».
3. Статус-отчёт со сдвигом плана без причины → ошибка; с причиной → «На погодженні», карточка без изменений; PMO погоджує → карточка показывает новую дату, в истории «Погодження звіту» и «Оновлено статус-звітом».
3a. PMO погоджує отчёт со сменой оценки без комментария → ошибка; с комментарием → стан карточки по оценке PMO, в истории «було → стало». PMO повертає отчёт → карточка без изменений, PM видит комментарий и заводит новый отчёт на основе возвращённого.
4. Статус-отчёт «Завершено», погоджений PMO → проект уходит в «Архів», карточка только для чтения.
4a. PM добавляет в команду человека без роли → ошибка; с ролью → строка в «Команда проєкту», после синхронизации человек видит проект; ссылка без `https://` → ошибка.
4b. Главная: показатели совпадают с отфильтрованными списками; щелчок по клетке карты рисков показывает её риски; в «Портфель за напрямами» — число проектов в каждом цвете и легенда.
5. Риск 5 × 4 → оценка 20, красная плашка «Високий».
6. Комментарий → появляется в карточке.
7. Пользователь без права правки → кнопок правки нет, замок с пояснением.
8. Переключение UA / EN / RU и светлой / тёмной темы — интерфейс переведён полностью.
9. После синхронизации: отчёт помечен применённым, журнал заполнен, права выданы, архивный проект — только чтение.
