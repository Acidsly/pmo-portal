# Тестування змін раунду 4 — PM

Портал: `https://smarthrua.sharepoint.com/sites/pmo-test` · Версія 1, 08.10.2026 · Версія порталу 1.7.2.1 · Інструкція в порталі — кнопка **?** угорі

## Як проходити тестування

- Цей план — лише про **зміни після раунду 3** (сповіщення, архів, відгуки № 59–78, новий вигляд). Попередні плани лишаються чинними.
- Перед початком оновіть сторінку порталу (**Ctrl+F5** / **Cmd+Shift+R**), щоб завантажилася нова версія.
- Виконуйте кроки по черзі й порівнюйте з колонкою «Що має бути». Розділ 7 — на телефоні.
- **Усе, що не збігається з планом, фіксуйте відгуком зі скриншотами**: вкладка **Відгуки** → **Залишити відгук** → номер кроку (наприклад, «2.3») і екран → що робили і що побачили.
- Це тестовий сайт: дані демонстраційні, нічого не зламаєте. «Свій проєкт» — де ви PM.

**Домовтеся з PMO про час.** Кроки 1.6 і 2.8 потребують рішення PMO: напишіть PMO, коли звіт надіслано.

Що зберігається у формах, видно одразу. Сповіщення, «Історія змін» і права оновлюються автоматично протягом ~15 хвилин.

## 1. Сповіщення

| № | Що зробити | Що має бути |
|---|---|---|
| 1.1 | Подивіться на дзвіночок угорі праворуч | Якщо є нові події ваших проєктів — червоне **число** (до 99, далі «99+»), дзвіночок час від часу похитується; немає — без числа |
| 1.2 | Натисніть дзвіночок | Вікно з міткою **«Сповіщення»**: події за 14 днів, нові вгорі (блакитні, «Нове»), переглянуті нижче (сірі); над списком «Нових: N» |
| 1.3 | Відкрийте одну нову подію | Відкривається картка, звіт або ризик; угорі **«← Сповіщення»**; число на дзвіночку зменшилось на 1 |
| 1.4 | Натисніть «← Сповіщення» | Список; відкрита подія тепер сіра, інші нові — блакитні |
| 1.5 | «Лише нові»; потім **«Позначити все прочитаним»** | «Лише нові» ховає переглянуте; після кнопки число на дзвіночку зникає, усі події сірі, кнопка зникає |
| 1.6 | PMO погоджує ваш звіт (домовтеся); через ~15 хвилин — дзвіночок | Нова подія «Погодження звіту» по вашому проєкту; ваші власні дії в сповіщеннях не показуються |

## 2. Статус-звіт

| № | Що зробити | Що має бути |
|---|---|---|
| 2.1 | Свій проєкт → **Додати статус-звіт** | Поля дати немає; рядок **«Дата подання: сьогодні · Період: з … по …»** і підказка «Дата подання — день збереження; період — від останнього погодженого звіту.» |
| 2.2 | Перевірте початок періоду | Дата останнього **погодженого** звіту проєкту (повернуті й на погодженні не враховуються); якщо погоджених немає — дата старту |
| 2.3 | Фаза **«Скасовано — перенести в архів»**; «Дата завершення (факт)» — **завтра** (введіть або оберіть у календарі) | Одразу, ще до збереження, під полем: «Не може бути пізніше дати подання (дд.мм.рррр). Майбутнє завершення вкажіть як прогноз.» |
| 2.4 | Дата факту **раніше дати старту** | «Не може бути раніше дати старту (дд.мм.рррр).» |
| 2.5 | Фаза «Завершено», факт — сьогодні, план і прогноз — пізніше | Помилки немає (дострокове завершення можна). Звіт не зберігайте, якщо не плануєте закривати проєкт |
| 2.6 | Позначте **«Потрібне рішення керівництва»**, поле «Яке рішення потрібне» залиште порожнім (або лише пробіли) → вийдіть із поля / Зберегти | Поле позначене «*»; «Зазначте, яке рішення потрібне від керівництва.»; зніміть позначку — поле не потрібне |
| 2.7 | Переключіть тему на темну (☾); оберіть оцінки «Терміни / Бюджет / Ресурси» | Вибраний варіант — синя рамка і ✓; невибрані світліші; при наведенні — підсвічуються |
| 2.8 | Подайте звіт, **не змінюючи фазу** (оцінки, резюме) → Зберегти; після погодження PMO — «Статус-звіти» | Колонка **«Фаза у звіті»** показує фазу проєкту (не «—»); у звіті — «Дата подання» і «Період: з … по …» |

## 3. Проєкти

| № | Що зробити | Що має бути |
|---|---|---|
| 3.1 | «Проєкти» → «Список» | Колонка **«Фаза проєкту»** (Ініціація, Планування, Реалізація, Призупинено); у картці й формі звіту — теж «Фаза проєкту» |
| 3.2 | Колонка «Звіт»: наведіть мишу на кольорову крапку | Підказка «Останній погоджений звіт — N дн. тому. Зелений — до 8 днів, жовтий — 9–14, червоний — понад 14.»; під датою — мітка «Погоджено» / «На погодженні · дата» / «Повернуто · дата» |
| 3.3 | Фільтр колонки «Звіт» (⏷) → «Повернуто» | Лише проєкти, у яких найновіший звіт повернуто; у фільтрі є й свіжість (до 8 днів, 9–14, понад 14) |
| 3.4 | Свій проєкт → «Редагувати проєкт» → у «Мета та опис» довгий текст (15+ рядків, з переносами) → Зберегти; відкрийте картку | Переноси рядків збережені; видно до 10 рядків і **«Показати повністю»**; після натискання — увесь текст і «Згорнути» |

## 4. Архів

| № | Що зробити | Що має бути |
|---|---|---|
| 4.1 | Вкладка «Архів» → «Список» | Колонка «Фаза проєкту» — **Завершено** (зелена) або **Скасовано** (сіра); колонка «Дата завершення / скасування» |
| 4.2 | «Відображати» → **«Завершені»**, потім **«Скасовані»**; відкрийте проєкт | Лише відповідні проєкти; картка — лише перегляд, без «Додати статус-звіт» і коментарів |

## 5. Вигляд

| № | Що зробити | Що має бути |
|---|---|---|
| 5.1 | Подивіться на шапку | Назва «PPM — Портфель проєктів» окремим рядком угорі; нижче — меню й кнопки (мова, тема, дзвіночок, «?») в одному рядку; у меню значки розділів кольором розділу |
| 5.2 | Відкрийте по черзі: картку проєкту, звіт, ризик, проблему, сповіщення, «?» | Угорі кожного вікна — кольорова мітка: «Проєкт», «Статус-звіт», «Ризик», «Проблема», «Сповіщення», «Довідка» — однаково, звідки б не відкрили |
| 5.3 | Темна тема (☾) — меню й мітки | Кольори розділів світліші, усе читається |
| 5.4 | «Відгуки» → відкрийте відгук | Біля номера стрілки **‹ ›** — попередній / наступний у порядку таблиці (з урахуванням фільтрів і сортування); на першому / останньому стрілка неактивна |
