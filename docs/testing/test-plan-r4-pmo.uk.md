# Тестування змін раунду 4 — PMO

Портал: `https://smarthrua.sharepoint.com/sites/pmo-test` · Версія 1, 08.10.2026 · Версія порталу 1.7.2.1 · Інструкція в порталі — кнопка **?** угорі

## Як проходити тестування

- Цей план — лише про **зміни після раунду 3** (сповіщення, архів, відгуки № 59–78, новий вигляд). Попередні плани лишаються чинними.
- Перед початком оновіть сторінку порталу (**Ctrl+F5** / **Cmd+Shift+R**), щоб завантажилася нова версія.
- Виконуйте кроки по черзі й порівнюйте з колонкою «Що має бути». Розділ 7 — на телефоні.
- **Усе, що не збігається з планом, фіксуйте відгуком зі скриншотами**: вкладка **Відгуки** → **Залишити відгук** → номер кроку (наприклад, «2.3») і екран → що робили і що побачили.
- Це тестовий сайт: дані демонстраційні, нічого не зламаєте.

**Домовтеся з PM про час.** Розділи 1–2 потребують дій PM: вони подають звіти (зокрема без зміни фази й «Скасовано» з фактичною датою), ви погоджуєте.

Що зберігається у формах, видно одразу. Сповіщення, «Історія змін» і права оновлюються автоматично протягом ~15 хвилин.

## 1. Сповіщення

| № | Що зробити | Що має бути |
|---|---|---|
| 1.1 | PM подає звіт (домовтеся); через ~15 хвилин — дзвіночок угорі праворуч | Червоне **число** нових подій, дзвіночок похитується; у списку — «Подання звіту» по проєкту PM |
| 1.2 | Натисніть дзвіночок | Вікно з міткою **«Сповіщення»**: події за 14 днів, нові вгорі (блакитні, «Нове»), над списком «Нових: N» |
| 1.3 | Відкрийте подію «Подання звіту» | Відкривається звіт (форма погодження); угорі **«← Сповіщення»**; число на дзвіночку зменшилось на 1 |
| 1.4 | «← Сповіщення» | Список; відкрита подія сіра, інші нові — блакитні |
| 1.5 | **«Позначити все прочитаним»** | Число на дзвіночку зникає, усі події сірі |
| 1.6 | Після погодження звіту «Завершено» / «Скасовано» (розділ 2) — дзвіночок | Подія «Проєкт в архіві»; ваші власні дії (погодження) в сповіщеннях не показуються |

## 2. Погодження звітів

| № | Що зробити | Що має бути |
|---|---|---|
| 2.1 | Відкрийте звіт на погодженні | Угорі мітка «Статус-звіт»; «Дата подання: дд.мм.рррр» і **«Період: з … по …»** (з дати останнього погодженого звіту проєкту) |
| 2.2 | Звіт, у якому PM **не змінював фазу** → Погодити; через ~15 хвилин — «Статус-звіти» | Колонка **«Фаза у звіті»** показує фазу (не «—»); фаза в картці не змінилась, в «Історії змін» рядка про фазу немає |
| 2.3 | PM подає наступний звіт по тому ж проєкту | Період нового звіту починається з дати звіту, який ви погодили в 2.2 |
| 2.4 | PM подає «Скасовано» з фактичною датою → Погодити; через ~15 хвилин — картка | Проєкт у «Архів» з фазою **«Скасовано»** і «Датою завершення / скасування»; PM не міг подати факт пізніше дати подання чи раніше старту і без опису рішення при позначці «Потрібне рішення керівництва» (перевіряє PM) |
| 2.5 | Темна тема (☾); у формі погодження змініть оцінку | Вибраний варіант — синя рамка і ✓; невибрані світліші |

## 3. Проєкти

| № | Що зробити | Що має бути |
|---|---|---|
| 3.1 | «Проєкти» → «Список»; головна — «Немає свіжого статус-звіту» | Колонка **«Фаза проєкту»** замість «Статус» |
| 3.2 | Колонка «Звіт»: наведіть мишу на кольорову крапку | Підказка «Останній погоджений звіт — N дн. тому. …»; під датою — «Погоджено» / «На погодженні · дата» / «Повернуто · дата» |
| 3.3 | Фільтр колонки «Звіт» (⏷) → **«На погодженні»**, потім **«Повернуто»** | Лише проєкти, де найновіший звіт чекає вашого рішення / повернутий; «Звіти не подавались» — проєкти без звітів |
| 3.4 | Картка проєкту з довгим описом (PM може внести 15+ рядків) | До 10 рядків і **«Показати повністю»** / «Згорнути»; переноси рядків збережені |

## 4. Архів

| № | Що зробити | Що має бути |
|---|---|---|
| 4.1 | Вкладка «Архів» → «Список» | Колонка «Фаза проєкту» — **Завершено** (зелена) / **Скасовано** (сіра); колонка «Дата завершення / скасування» |
| 4.2 | «Відображати» → **«Завершені»**, **«Скасовані»** | Лише відповідні проєкти |
| 4.3 | Головна → «Динаміка стану портфеля» | Скасовані проєкти враховуються до дати скасування, як завершені — до дати завершення |

## 5. Вигляд

| № | Що зробити | Що має бути |
|---|---|---|
| 5.1 | Подивіться на шапку | Назва окремим рядком угорі; нижче — меню й кнопки в одному рядку; значки розділів кольором розділу |
| 5.2 | Відкрийте: картку, звіт, ризик, «Призначення» (Змінити PM / власника), сповіщення, «?» | Угорі кожного вікна — кольорова мітка: «Проєкт», «Статус-звіт», «Ризик» / «Проблема», «Призначення», «Сповіщення», «Довідка» |
| 5.3 | Темна тема — меню й мітки | Кольори розділів світліші, усе читається |
| 5.4 | «Відгуки» → відкрийте відгук | Біля номера стрілки **‹ ›** — попередній / наступний у порядку таблиці; на краях стрілка неактивна |
