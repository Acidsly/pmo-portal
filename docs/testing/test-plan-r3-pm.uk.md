# Тестування змін раунду 3 — PM

Портал: `https://smarthrua.sharepoint.com/sites/pmo-test` · Версія 5, 04.10.2026 · Версія порталу 1.7.0.17 · Інструкція в порталі — кнопка **?** угорі

## Як проходити тестування

- Цей план — лише про **зміни за вашими відгуками раунду 3**. Повний план (версія 4) лишається чинним.
- Перед початком оновіть сторінку порталу (**Ctrl+F5** / **Cmd+Shift+R**), щоб завантажилася нова версія.
- Виконуйте кроки по черзі й порівнюйте з колонкою «Що має бути». Блок 7 — на телефоні.
- **Усе, що не збігається з планом, фіксуйте відгуком зі скриншотами**: вкладка **Відгуки** → **Залишити відгук** → номер кроку (наприклад, «1.4») і екран → що робили і що побачили. Номер вашого відгуку тепер видно в першій колонці «№».
- Це тестовий сайт: дані демонстраційні, нічого не зламаєте. «Свій проєкт» — де ви PM.

**Домовтеся з PMO про час.** Кроки 2.3, 3.2 і розділ 6 потребують рішень PMO: напишіть PMO, коли звіти надіслано. Для розділу 6 оберіть разом із PMO проєкт, де PMO змінить PM.

Що зберігається у формах, видно одразу. Права доступу й «Історія змін» оновлюються автоматично протягом ~15 хвилин.

## 1. Форма статус-звіту

| № | Що зробити | Що має бути |
|---|---|---|
| 1.1 | Картка свого проєкту → **Додати статус-звіт** | Проєкт у формі зафіксовано (вибрати інший не можна) |
| 1.2 | «Статус-звіти» → **Новий статус-звіт** | За замовчуванням — проєкт без звіту на погодженні; проєкти зі звітом на погодженні в списку недоступні, з позначкою «звіт від … на погодженні» |
| 1.3 | Нічого не заповнюйте → **Зберегти** | «Заповніть усі обов'язкові поля, позначені *.»; підсвічено оцінки, резюме та інші обов'язкові поля одразу |
| 1.4 | «% виконання»: введіть 500; потім 00098 і вийдіть із поля | 500 — «Введіть ціле число від 0 до 100.» під полем; 00098 стає 98 |
| 1.5 | Статус **«Завершено — перенести в архів»**, потім інший статус | При «Завершено» — 100 %, поле закрите, «Проєкт завершується — 100 %.»; після зміни статусу повертається попереднє значення |
| 1.6 | «Дата завершення (план)» раніше «Дати старту» → Зберегти | Під полем «Не може бути раніше дати старту.» |
| 1.7 | Подивіться на форму; «Витрати на дату, $»: 1450000, вийдіть із поля | «Терміни / Бюджет / Ресурси» — кожна оцінка одним рядком; статус, % і витрати — в одному ряду; витрати показуються «1 450 000» |

## 2. Фактична дата завершення (#54)

| № | Що зробити | Що має бути |
|---|---|---|
| 2.1 | Новий звіт, статус **«Скасовано — перенести в архів»** | З'являється «Дата завершення (факт) *» з підказкою «Коли проєкт фактично завершено або скасовано.»; для «Реалізація» поля немає |
| 2.2 | Залиште дату порожньою → Зберегти; потім дата **пізніше дати звіту**; потім **раніше старту** | Порожня — поле підсвічено, «Заповніть усі обов'язкові поля…»; пізніше — «Не може бути пізніше дати звіту.»; раніше старту — «Не може бути раніше дати старту.» |
| 2.3 | Правильна дата → Зберегти (на проєкті, який можна закрити, домовтеся з PMO) | Звіт на погодженні; після погодження PMO проєкт в «Архів», у картці «Дата завершення (факт)», в архіві — колонка «Завершено (факт)» |

## 3. Звіти й історія (#42, #46)

| № | Що зробити | Що має бути |
|---|---|---|
| 3.1 | Відкрийте свій надісланий звіт | Лише перегляд — кнопки зміни немає; у картці кнопка «Редагувати проєкт» змінює картку, а не звіт |
| 3.2 | Звіт, який PMO повернув: картка → **«Новий звіт на основі повернутого»** → Зберегти | Форма заповнена даними повернутого звіту; новий звіт — на погодженні |
| 3.3 | Через ~15 хвилин — картка → «Історія змін» | «Подання звіту» для кожного поданого звіту; для 3.2 — «Новий звіт на основі повернутого від дд.мм.рррр · …»; посилання **«Відкрити звіт →»** відкриває цей звіт |

## 4. Ризики та проблеми (#47, #48, #55)

| № | Що зробити | Що має бути |
|---|---|---|
| 4.1 | «Ризики та проблеми» → **«Новий ризик / проблема»**; у картці — **«Додати ризик / проблему»** | Форма: перше поле після проєкту — «Тип» (Ризик / Проблема), далі «Опис *»; заголовок «Новий ризик» |
| 4.2 | Оберіть «Проблема»; заповніть опис → Зберегти | Заголовок змінюється на «Нова проблема»; запис збережено |
| 4.3 | Змініть цей запис: статус «В роботі», ймовірність, термін; потім закрийте («Закрито»). Через ~15 хвилин — «Історія змін» картки | «Ризик / проблема»: «Додано», зміни полів «було → стало» (статус, ймовірність, оцінка, термін), «Закрито: …»; посилання **«Відкрити ризик →»** |

## 5. Проєкти й таблиці

## 6. Зміна PM (разом із PMO, #43)

| № | Що зробити | Що має бути |
|---|---|---|
| 6.1 | У картці свого проєкту шукайте «Змінити PM / власника» | Кнопки немає — змінює лише PMO |
| 6.2 | PMO змінює PM обраного проєкту на іншого PM групи; відкрийте картку | Одразу видно нового PM, «Призначення» в історії; ви більше не можете додати звіт чи редагувати проєкт; ваш звіт «на погодженні» (якщо був) повертається з коментарем «Змінився PM проєкту — новий PM подає актуальний звіт.» |
| 6.3 | Новий PM відкриває картку | Спочатку плашка «Ви призначені PM цього проєкту: права редагування з'являться протягом 15 хвилин.», потім — «Додати статус-звіт» і «Редагувати проєкт» |
